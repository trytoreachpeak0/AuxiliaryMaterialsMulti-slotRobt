---

## 1. 一句话背景

发货柜（多格口焊丝柜）配套的工业一体机软件。两类角色各用一个界面：

- **操作员 OP**：归还旧焊丝（存入归还格口）+ 领用新焊丝（从领用格口取出）。
- **物料员 MH**：把可用焊丝存入空闲格口，以及批量/单个开关格口门、查看柜体状态。

界面通过顶部「操作员 OP / 物料员 MH」标签切换。

## 2. 运行方式

```powershell
cd WireDispenser.Demo
dotnet run
```

- 技术栈：**WPF + .NET 8**（`net8.0-windows`），见 `WireDispenser.Demo.csproj`。
- 目前无第三方依赖、无 MVVM 框架、无 DI 容器。

## 3. ⚠️ 必须遵守的界面约束（改逻辑时不要破坏）

目标设备：**工业一体机，1024×768（4:3），12.1 英寸，电容触控**。因此：

1. **固定窗口**：`Width=1024 Height=768`、`WindowStyle="None"`、`ResizeMode="NoResize"`。
2. **禁止滚动**：任何视图都不要引入 `ScrollViewer` / 让内容溢出。所有信息必须在一屏内排布（MhView 的格口网格用 `Viewbox` 自适应缩放，不是滚动）。
3. **字号下限**（见 `Styles/IndustrialTheme.xaml`）：正文 ≥ 14，关键值 ≥ 17，标题 ≥ 18。
4. **触控目标**：输入框/按钮最小高度约 42px，主按钮 44~46px。
5. **工厂风格**：朴素、对比清晰，不要花哨动画/渐变。
6. 配色、控件样式**统一走 `IndustrialTheme.xaml` 里的资源键**，不要在视图里硬编码新颜色。

`MainWindow.xaml.cs` 现有逻辑：

- 构造时创建 `OpView` / `MhView` 单例，默认显示 OP。

**建议接入点：**

- `StatusText` 是全局状态出口。建议提供一个可被各视图调用的方法（如 `MainWindow.SetStatus(string)`，或 ViewModel 上的 `StatusMessage` 属性 + 绑定），用于展示**当前流程步骤 / 操作提示 / 校验结果**（例如「请放入归还焊丝并关闭格口门」「操作员不存在，请重新输入」）。

## 7. OpView（操作员）—— 现状逐区块说明 + 待补逻辑

整体为 `Grid`（无滚动），自上而下分 4 个输入步骤 + 底部 2 个柜口动作阶段。对应流程图 `操作员存入归还焊丝取出可用焊丝.md` 的「二、归还焊丝 + 三、领用焊丝」。

> **当前所有输入框/显示框/按钮都没有 `x:Name`，也没有事件**。接入逻辑的第一步通常是：给需要读写的控件加 `x:Name`（或改造为数据绑定/Command），再挂事件。

### 步骤① 操作员身份（Row 0）

- **UI**：操作员ID `TextBox`（占位 `E10086`）、班组 `ComboBox`、班次 `ComboBox`、姓名只读框（占位「张三」）、「校验」按钮。
- **对应流程节点**：`inputOPId → queryOPById → checkOPIdExists →(是) showOPName /(否) showOPIdNotExistsMessage`。
- **待补**：点「校验」→ 按工号查 MES 操作人员（见 `mes-sql` 中操作员相关查询 / `mv_fw_username` 表）→ 存在则回填姓名并放行下一步；不存在则在状态栏/界面提示并要求重输。

### 步骤② 焊丝批号（Row 2 左）

- **UI**：归还焊丝批号 `TextBox`（占位 `WB-2026-05-28-001`）、「查询」按钮、结果框（焊丝类型 / 匹配可用焊丝 / 归还重量，均为占位）。
- **对应流程节点**：`inputReturnedWireLotNo → queryWireSpecByLotNo → checkWireLotNoExists → checkWireSpecExists → queryMatchedAvailableWire → checkMatchedWireExists`，随后 `queryWireReturnedWeightBySpec → checkReturnedWeightExists`。
- **待补**：
  1. 按批号查焊丝规格（批号不存在/不合法 → 提示重输）。
  2. 规格不存在 → 提示。
  3. 查「发货柜内是否有匹配的同规格**可用**焊丝」→ 无匹配 → 提示「请到物料间领取」并结束流程。
  4. 查该焊丝类型的**归还重量**（来自应用数据库）→ 不存在 → 提示「请到物料间人工归还」并结束。
- 结果框三项（焊丝类型 / 匹配可用焊丝 / 归还重量）需替换为真实查询结果。

### 步骤③ 机台信息（Row 2 右）

- **UI**：机台号 `TextBox`（占位 `M-0312`）、「校验」按钮、结果框（工单批次号 / 领用格口 / 归还格口，均为占位）。
- **对应流程节点**：`inputEqpNo → queryEqpByEqpNo → checkEqpNoExists`，随后 `queryLastProductLotNo → checkLastProductLotNoExists`。
- **待补**：
  1. 校验机台号是否存在（不存在 → 提示重输）。
  2. 查该机台**最近生产的产品/工单批次号**（查不到 → 提示「请到物料间人工归还」并结束）。
  3. 「领用格口 / 归还格口」需由柜体业务分配后回填（见第 9 节格口状态机）。

### 步骤④ 剩余芯片 / 用量校验（Row 4）

- **UI**：剩余待焊芯片数量 `TextBox`（占位 `1280`）、实际用量差显示框（单位米，绿色「校验通过」）。
- **对应流程节点**：`inputRemainingQty → queryWireQuotaCheck →(成功) 进入归还提交 /(ORA-20007) showRemainingQtyWrongHint（重输）`。
- **待补**：用 MES `Get_Mat_QuotaCheck` 查实际与理论消耗差值（米）；成功返回任意数值即通过；ORA-20007 时红色提示并要求重输。

### 步骤⑤ 存入归还焊丝（Row 6 左）—— 本次新增

- **UI**：归还格口（占位 `R05`）、提示「发货柜将打开归还格口，请放入归还焊丝并关闭格口门」、「提交归还焊丝」按钮。
- **对应流程节点**：`submitWireReturn → checkSubmitWireReturnSuccess →(是) showWireReturnSuccessMessage → openReturnSlot → showLoadWireAndCloseDoorMessage → loadReturnedWire → closeReturnSlotDoor`。
- **待补**：
  1. 点「提交归还焊丝」→ 提交归还请求到 MES（失败 → 展示 MES 返回文本或数据库异常原文，并结束）。
  2. 成功 → 命令柜体**打开归还格口** → 状态栏提示放入并关门 → 检测格口门关闭信号 → 进入领用阶段。

### 步骤⑥ 取出可用焊丝（Row 6 右）—— 本次新增

- **UI**：领用格口（占位 `A03`）、提示「发货柜将打开领用格口，请取出可用焊丝并关闭格口门」、「提交领用焊丝」按钮。
- **对应流程节点**：`queryWireByLotNo + queryProductByLotNo（校验信息存在）→ submitWireIssue → checkSubmitWireIssueSuccess →(是) showWireIssueSuccessMessage → openIssueSlot → unloadWire → closeIssueSlotDoor → 结束`。
- **待补**：
  1. 校验可用焊丝信息 / 产品批次信息存在（任一不存在 → 提示并结束）。
  2. 提交领用请求（失败 → 展示 MES 返回文本或数据库异常原文，并结束）。
  3. 成功 → 命令柜体**打开领用格口** → 提示取出并关门 → 检测关门 → 流程结束、界面复位。

> **交互流程（0.1 已定稿，Demo 已实现骨架）**：OP 为**强顺序**流程（身份→批号→机台→芯片→归还→领用）。规则见 `requirements/versions/0.1/docs/OP界面-分步交互规范.md`：
> - 初始仅步骤①可输入，后续步骤置灰且禁用；
> - 某步「校验/查询/提交」通过后锁定该步，再点亮下一步；
> - 清空当前可编辑步的主输入 → 级联清空该步及之后所有步（已完成且锁定的更早步骤不变）；
> - 「重新开始」复位全流程。
>
> 参考代码：`Views/OpStepFlow.cs`、`OpView.xaml.cs`。异常分支统一走 `MainWindow.SetStatus` 提示。

  - 有料/待发放 `SlotLoadedBrush` + `SlotLoadedBorderBrush`
  - 归还/退回 `SlotReturnedBrush` + `SlotReturnedBorderBrush`

## 10. 建议的接入架构（二选一）

**A. 推荐：引入轻量 MVVM**
- 为 `OpView` / `MhView` 各建一个 `ViewModel`，承载：输入属性、查询结果属性、各步骤 `IsEnabled`、`StatusMessage`、各按钮 `ICommand`。
- 新建 `Services` 层：`IMesService`（查询/提交，按 `sql_id` 调 MES）、`ICabinetService`（开门/读门状态/格口分配）、`IAppDb`（归还重量、格口业务信息）。
- 视图只做绑定，业务逻辑在 VM/Service，便于单测与替换真实硬件。

**B. 最小改动：code-behind**
- 给控件加 `x:Name`，在 `*.xaml.cs` 里写 `Click`/`TextChanged`，直接调用 Service。
- 适合快速打通，但请仍把 MES/柜体访问抽到 Service，不要把 SQL/串口代码直接写进视图。

无论哪种：**MES 查询、柜门控制都应是异步的，并在执行期间禁用相关按钮、在状态栏提示进行中**，避免触屏重复点击。
