# 复合机器人发货柜需求规格说明书

## 1. 文档说明

### 1.1 文档目的

本文档用于描述半导体封装工厂内“AGV + 多格口发货柜”复合机器人系统的一期业务需求、功能边界、接口边界、核心流程、防呆防混批要求、异常处理要求和验收标准。

本文档作为后续系统设计、接口设计、开发排期、测试用例编写和项目验收的基础依据。

### 1.2 项目定位

本项目建设的是一套面向半导体封装工厂内部物料配送与发放场景的复合机器人发货柜控制系统。

系统形态为：

- 一台 AGV 固定搭载一个发货柜。
- 一个发货柜包含多个格口，也可称为仓位。
- 不同发货柜型号的格口数量、格口尺寸、电子锁地址、传感器配置可能不同。
- AGV 主要作为发货柜的移动载体，只需要按任务到达指定固定站点；本系统只向 RCS 下发目标站点相关指令，不考虑 AGV 如何行驶、如何规划路径或如何协调通行。
- 系统通过本地部署方式运行。
- 系统与 MES、RCS、发货柜控制硬件进行集成。

### 1.3 一期建设目标

一期目标是实现可在生产环境试运行的单车单柜业务闭环，重点降低复杂度，优先保证稳定性、防呆能力和可追溯能力。

一期系统应实现：

- 单台 AGV 控制业务闭环。
- 单个固定搭载式发货柜控制。
- 多格口配置与锁控。
- 固定站点之间的任务执行。
- MES 轮询接单。
- 人工界面创建任务。
- RCS HTTP 接口调用。
- 不同物料类型的差异化存取流程。
- OP 身份校验与绑定。
- 防错料、防混批、防误开门。
- 任务全流程追溯。
- 异常告警与人工干预。

### 1.4 非一期范围

以下内容不纳入一期范围，后续可作为二期或扩展需求：

- 多台 AGV 协同调度。
- 一台 AGV 搭载多个货柜。
- 多货柜切换顶升或换柜。
- 复杂路径规划。
- AGV 交通管制。
- AGV 避障算法。
- RCS 系统开发。
- 复杂库存管理系统。
- WMS、ERP 等系统集成。
- 云端平台。
- 洁净室、ESD 等硬件环境要求。

## 2. 术语定义

### 2.1 AGV

自动导引运输车。本项目中 AGV 只作为发货柜的移动载体，负责把发货柜送到指定站点。AGV 的移动执行、路径规划、通行协调、到站反馈和运行状态由外部 RCS 提供。

### 2.2 发货柜

固定安装在 AGV 上的多格口柜体。发货柜随 AGV 移动，不支持一个 AGV 同时顶多个货柜。

### 2.3 格口/仓位

发货柜内的独立存取空间。每个格口至少具备独立电子锁。部分格口可配置物体检测传感器，用于判断格口内是否有物体。

### 2.4 RCS

机器人调度控制系统。RCS 负责接收目标站点指令并控制 AGV 到达指定站点，同时提供 AGV 状态和到站结果。本项目系统只通过 HTTP 接口调用 RCS，不实现 RCS 内部能力，也不处理 AGV 如何行驶的问题。

### 2.5 MES

制造执行系统。MES 可通过接口提供物料配送任务，并接收本系统回传的任务状态、执行结果和异常信息。

### 2.6 OP

工厂操作员。部分物料的存货、取货、确认、异常处理操作需要与 OP 身份绑定。

### 2.7 流程模板

用于描述某类物料或某类业务任务的执行规则，包括是否需要扫码、是否需要 OP 认证、是否校验批次、是否允许混批、是否需要传感器确认、与 MES 的交互步骤等。

## 3. 系统边界

### 3.1 系统负责内容

本系统负责：

- 从 MES 轮询任务。
- 支持人工创建任务。
- 将外部任务转换为内部统一任务。
- 管理任务状态机。
- 管理固定站点与任务执行顺序。
- 调用 RCS 下发目标站点指令，使 AGV 到达指定站点。
- 控制发货柜格口开锁。
- 读取格口电子锁状态。
- 读取格口物体检测传感器状态。
- 根据物料类型执行不同的存取流程。
- 校验 OP 身份。
- 校验物料、批次、工单、数量、站点等信息。
- 执行防错料、防混批、防误开门规则。
- 记录任务、接口、开锁、扫码、身份认证、异常和人工干预日志。
- 提供本地管理界面。

### 3.2 系统不负责内容

本系统不负责：

- AGV 如何从当前站点行驶到目标站点。
- AGV 底盘运动控制。
- AGV 定位算法。
- AGV 避障算法。
- AGV 地图管理。
- 多车交通管制。
- RCS 内部任务调度算法。
- MES 生产业务规则。
- 物料实物包装标准制定。
- 硬件洁净室和 ESD 设计。

### 3.3 一期部署边界

一期系统采用本地局域网部署。

系统需要与以下对象通过局域网通信：

- MES。
- RCS。
- 发货柜控制器。
- 本地客户端或浏览器。
- 身份认证设备或扫码设备。

## 4. 业务场景

### 4.1 核心业务场景

一期核心场景为移动式定点发货柜。

AGV 搭载发货柜在固定的若干站点之间移动。本系统根据任务决定目标站点，并向 RCS 下发目标站点相关指令；AGV 如何移动到站点由 RCS 负责。AGV 到达某个站点后，发货柜在该站点等待 OP 装入物料或领取物料。系统根据任务、物料类型、OP 权限和流程模板控制允许打开的格口，并记录操作结果。

### 4.2 典型站点

系统应支持维护固定站点基础数据。

站点类型可包括：

- 装货站点。
- 发货站点。
- 取货站点。
- 等待站点。
- 异常处理站点。
- 充电或停靠站点。

一期可根据现场实际情况配置有限数量站点，系统不需要支持复杂动态路径选择。

### 4.3 任务来源

系统应支持以下任务来源：

- MES 任务：系统通过轮询 MES 接口获取。
- 人工任务：由授权用户通过系统界面创建。

所有任务进入系统后，应转换为统一的内部任务模型，并按统一状态机执行。

### 4.4 物料差异化流程

不同物料可能具有不同的存取要求。

系统应支持按物料、物料类型、任务类型或业务流程配置流程模板。流程模板至少应支持配置：

- 装货是否需要扫码。
- 取货是否需要扫码。
- 装货是否需要 OP 身份认证。
- 取货是否需要 OP 身份认证。
- 是否绑定存货 OP。
- 是否绑定领货 OP。
- 是否校验料号。
- 是否校验批次。
- 是否校验工单。
- 是否校验数量。
- 是否校验目标站点。
- 是否允许混批。
- 是否允许同格口多物料。
- 是否需要传感器确认物体存在。
- 是否需要人工确认。
- 是否需要 MES 装货前校验。
- 是否需要 MES 取货前校验。
- 是否需要 MES 完成后回传。

## 5. 用户角色与权限

### 5.1 管理员

管理员可执行：

- 用户管理。
- 权限配置。
- 站点配置。
- 发货柜配置。
- 格口配置。
- 流程模板配置。
- 接口参数配置。
- 异常任务人工关闭。
- 强制开锁。
- 查看全部日志。

强制开锁等高风险操作必须记录操作人、操作时间、原因和关联任务。

### 5.2 班组长/主管

班组长或主管可执行：

- 查看任务状态。
- 查看异常告警。
- 人工创建任务。
- 处理部分异常。
- 授权 OP 重新操作。
- 查看本班组相关日志。

### 5.3 OP 操作员

OP 可执行：

- 登录或身份认证。
- 按任务要求装货。
- 按任务要求取货。
- 扫码确认物料。
- 确认操作完成。
- 查看与本人相关的任务提示。

OP 不应具备越权开锁、关闭异常任务、修改流程模板等权限。

### 5.4 系统接口用户

系统接口用户用于 MES、RCS 等系统间调用。接口用户应具备独立凭证和权限范围，不应与人工账号混用。

## 6. 基础数据需求

### 6.1 AGV 基础数据

系统应维护当前唯一 AGV 信息。

字段建议包括：

- AGV 编号。
- AGV 名称。
- RCS 设备编号。
- 当前绑定发货柜编号。
- 启用状态。
- 当前站点。
- 当前运行状态。

一期业务规则限制系统同时只能启用一台 AGV。

### 6.2 发货柜基础数据

系统应维护发货柜信息。

字段建议包括：

- 发货柜编号。
- 发货柜名称。
- 发货柜型号。
- 绑定 AGV 编号。
- 格口数量。
- 控制器地址。
- 通信协议。
- 启用状态。

一期业务规则限制一台 AGV 只绑定一个发货柜。

### 6.3 格口基础数据

系统应维护每个格口配置。

字段建议包括：

- 格口编号。
- 所属发货柜编号。
- 格口显示名称。
- 格口序号。
- 电子锁地址。
- 是否启用。
- 是否有物体检测传感器。
- 传感器地址。
- 格口尺寸或类型。
- 当前格口状态。

不同型号发货柜的格口数量不固定，系统不得写死格口数量。

### 6.4 站点基础数据

系统应维护站点信息。

字段建议包括：

- 站点编号。
- 站点名称。
- RCS 站点编码。
- 站点类型。
- 是否启用。
- 是否允许装货。
- 是否允许取货。
- 是否允许等待。

### 6.5 物料基础数据

系统应支持维护或缓存物料信息。

字段建议包括：

- 物料编码。
- 物料名称。
- 物料类型。
- 默认流程模板。
- 是否受控物料。
- 是否需要 OP 绑定。
- 是否允许混批。

物料单位、包装形态不应在系统中写死。系统应支持不同任务携带不同单位描述。

### 6.6 流程模板基础数据

系统应支持配置不同流程模板。

流程模板应用于控制不同物料、不同任务或不同来源任务的差异化执行逻辑。

## 7. 任务模型需求

### 7.1 任务基本信息

任务应至少包含：

- 任务编号。
- 任务来源。
- 外部任务编号。
- 任务类型。
- 任务优先级。
- 起始站点。
- 目标站点。
- 当前状态。
- 关联 AGV。
- 关联发货柜。
- 关联流程模板。
- 创建时间。
- 更新时间。
- 完成时间。
- 异常原因。

### 7.2 任务明细信息

任务应支持多个明细。

任务明细应至少包含：

- 明细编号。
- 任务编号。
- 物料编码。
- 物料名称。
- 物料类型。
- 批次号。
- 工单号。
- 数量。
- 单位。
- 目标格口。
- 存货 OP。
- 领货 OP。
- 明细状态。

### 7.3 格口绑定关系

系统应支持任务明细与格口绑定。

绑定关系应至少记录：

- 任务编号。
- 任务明细编号。
- 发货柜编号。
- 格口编号。
- 绑定时间。
- 绑定方式。
- 当前绑定状态。

格口绑定方式可包括：

- 系统自动分配。
- 人工指定。
- MES 指定。

### 7.4 任务状态

任务状态建议包括：

- 已创建。
- 待校验。
- 待装货。
- 装货中。
- 装货完成。
- 待派车。
- 已派车。
- AGV 行驶中。
- 到达目标站点。
- 待取货。
- 取货中。
- 取货完成。
- 已完成。
- 已取消。
- 异常。

系统应保证任务状态变化可追溯，不允许无记录地跳转状态。

### 7.5 格口状态

格口状态建议包括：

- 空闲。
- 已预占。
- 待装货。
- 已开锁。
- 已装货。
- 运输中。
- 待取货。
- 已取货。
- 异常锁定。
- 禁用。

格口状态应独立于任务状态管理。任务异常时，应能准确定位受影响格口。

## 8. 核心业务流程需求

### 8.1 MES 任务接入流程

系统应按配置周期轮询 MES 任务接口。

流程要求：

1. 系统按固定周期请求 MES 待执行任务。
2. 系统校验任务编号是否重复。
3. 系统校验任务数据完整性。
4. 系统根据物料或任务类型匹配流程模板。
5. 系统创建内部任务。
6. 系统向 MES 回传任务已接收或接收失败结果。

系统应支持 MES 接口异常时自动重试，并记录接口异常日志。

### 8.2 人工任务创建流程

系统应支持授权用户通过界面创建任务。

流程要求：

1. 用户选择任务类型。
2. 用户选择起始站点和目标站点。
3. 用户录入或扫码录入物料信息。
4. 用户选择流程模板，或由系统根据物料自动匹配。
5. 系统校验任务信息。
6. 系统创建内部任务。

人工任务应与 MES 任务使用相同的任务状态机。

### 8.3 装货流程

装货流程应由流程模板控制。

通用流程要求：

1. AGV 到达装货站点，或当前已处于允许装货的固定站点。
2. 系统显示待装货任务和目标格口。
3. 如流程要求 OP 认证，OP 必须先完成身份认证。
4. 如流程要求扫码，OP 必须扫描物料码、批次码、工单码或其他指定条码。
5. 系统校验扫码结果是否与任务匹配。
6. 系统校验格口是否可用。
7. 系统打开指定格口电子锁。
8. OP 放入物料。
9. 如格口配置物体检测传感器，系统根据流程模板判断是否必须检测到物体。
10. OP 关闭格口。
11. 系统确认电子锁或门状态已关闭。
12. 系统记录装货完成信息。

如果流程模板不要求扫码，系统仍应记录操作人、操作时间、任务和格口信息。

### 8.4 派车与移动流程

派车流程要求：

1. 系统确认任务已完成装货。
2. 系统确认所有参与任务的格口均已关闭。
3. 系统确认发货柜无禁止移动的异常。
4. 系统向 RCS 下发移动任务。
5. 系统轮询 RCS 获取 AGV 状态。
6. RCS 返回到达目标站点后，系统进入到站处理流程。

系统不得在存在格口未关闭、电子锁异常、柜体通信异常等风险状态时下发移动任务。

### 8.5 取货流程

取货流程应由流程模板控制。

通用流程要求：

1. AGV 到达目标站点。
2. 系统显示可取货任务。
3. 如流程要求 OP 认证，OP 必须先完成身份认证。
4. 如流程要求扫码，OP 必须扫描取货凭证、物料码、批次码、工单码或其他指定条码。
5. 系统校验 OP 是否有权限领取。
6. 系统校验取货站点是否正确。
7. 系统打开指定格口电子锁。
8. OP 取出物料。
9. 如格口配置物体检测传感器，系统根据流程模板判断是否必须检测到物体已取出。
10. OP 关闭格口。
11. 系统确认电子锁或门状态已关闭。
12. 系统记录取货完成信息。
13. 系统按流程模板要求回传 MES。

### 8.6 固定等待流程

系统应支持 AGV 到达固定等待站点后保持等待状态。

等待状态下可发生：

- 等待 MES 下发任务。
- 等待人工创建任务。
- 等待 OP 装货。
- 等待 OP 取货。
- 等待异常处理。

系统应显示当前 AGV 所在站点、等待原因、可操作任务和异常信息。

## 9. 流程模板需求

### 9.1 流程模板配置原则

由于不同物料的存取流程可能不同，系统不应将扫码、身份认证、MES 交互、防混批规则写死在单一流程中。

系统应通过流程模板实现差异化流程控制。

流程模板的目标是让现场业务规则可以在系统配置中调整，而不是每次变更存取流程都修改代码。系统应支持通过配置调整不同物料、不同任务类型、不同任务来源对应的操作步骤和校验规则。

一期不要求建设完全自由编排的流程引擎。系统应优先支持有限但明确的流程配置项，例如扫码、身份认证、MES 校验、传感器确认、防混批、人工确认、异常放行等，以降低项目复杂度并保证生产稳定性。

### 9.2 流程模板配置项

流程模板应至少支持以下配置项：

- 模板编号。
- 模板名称。
- 适用任务类型。
- 适用物料类型。
- 装货是否需要 OP 认证。
- 装货是否需要扫码。
- 装货扫码字段要求。
- 装货是否需要 MES 校验。
- 装货是否需要传感器确认。
- 取货是否需要 OP 认证。
- 取货是否需要扫码。
- 取货扫码字段要求。
- 取货是否需要 MES 校验。
- 取货是否需要传感器确认。
- 是否允许混批。
- 是否允许同格口多物料。
- 是否绑定存货 OP。
- 是否绑定领货 OP。
- 是否允许非指定 OP 代取。
- 超时处理方式。
- 异常处理方式。
- 是否允许主管或管理员人工放行。
- MES 状态回传节点。
- 柜端界面提示内容。

### 9.3 流程模板执行要求

系统执行任务时，应根据任务绑定的流程模板动态决定用户界面步骤、校验规则、接口调用和格口控制行为。

系统应记录任务实际使用的流程模板版本，避免后续模板修改影响历史任务追溯。

流程模板修改后，应只影响新创建任务。已经创建或正在执行的任务应继续使用创建任务时绑定的模板版本，避免执行过程被中途改变。

### 9.4 流程模板示例

系统可预置或配置以下典型流程模板：

- 普通辅料流程：装货需要扫描物料码，取货只需要确认，不强制绑定指定 OP。
- 受控物料流程：装货和取货均需要 OP 身份认证，需校验物料、批次、工单，并绑定存货 OP 和领货 OP。
- 人工配送流程：由人工界面创建任务，不依赖 MES 任务，但仍记录物料、格口、OP 和任务过程。
- 传感器强校验流程：装货后必须检测到格口有物体，取货后必须检测到格口无物体；传感器异常时任务进入异常或等待授权处理。
- MES 强校验流程：装货前、取货前或完成后需要与 MES 交互确认，具体交互节点由流程模板配置。

## 10. 防呆与防混批需求

### 10.1 防错料

防错料是指防止错误物料进入任务流程，或防止 OP 从错误格口领取错误物料。系统应支持装货和取货时校验物料编码。

当任务要求配送某个物料时，系统应根据流程模板判断是否需要通过扫码、MES 校验或人工确认来验证物料。对于需要强校验的物料，校验不通过时不得继续执行。

当扫码结果与任务物料不一致时：

- 系统应阻止继续操作。
- 系统不得打开目标格口。
- 系统应提示错误原因。
- 系统应记录异常日志。

### 10.2 防混批

防混批是指防止不同批次的物料被错误地作为同一任务、同一格口或同一工单的物料处理。系统应支持按流程模板配置是否允许混批。

当任务或物料不允许混批时：

- 同一格口不得绑定多个批次。
- 同一任务明细不得被错误批次替代。
- 扫码批次与任务批次不一致时应禁止操作。

### 10.3 防错工单

系统应支持校验工单号。

当流程模板要求校验工单时，工单号不一致应禁止装货或取货。

### 10.4 防错站点

系统应校验 AGV 当前站点。

未到达指定站点时：

- 系统不得打开任务格口。
- 系统不得允许 OP 完成取货。
- 系统应提示当前站点不匹配。

### 10.5 防误开门

防误开门是指防止非当前任务、非授权人员、非指定站点或非安全状态下打开格口。系统应满足：

- 只有任务绑定格口允许打开。
- 非当前任务格口不得由普通 OP 打开。
- AGV 行驶中不得打开任何格口。
- 格口异常锁定时不得普通开锁。
- 强制开锁必须由授权用户执行并填写原因。

### 10.6 OP 绑定

系统应支持存货 OP 和领货 OP 绑定。

当流程模板要求指定 OP 取货时：

- 非指定 OP 不得打开格口。
- 系统应记录非法尝试。
- 管理员或主管可按权限授权代取。

## 11. 发货柜控制需求

### 11.1 电子锁控制

系统应支持对每个格口独立开锁。

系统应支持读取电子锁状态，至少包括：

- 已锁。
- 已开。
- 状态未知。
- 锁异常。

### 11.2 物体检测传感器

部分格口具有物体检测传感器。

系统应支持按格口配置是否存在传感器。

对于配置传感器的格口，系统应支持读取：

- 有物体。
- 无物体。
- 传感器异常。
- 状态未知。

是否必须使用传感器结果完成装货或取货确认，应由流程模板决定。

### 11.3 格口开锁规则

系统开锁前应校验：

- AGV 当前状态允许开锁。
- 当前站点允许开锁。
- 当前任务状态允许开锁。
- 当前格口与任务绑定关系正确。
- 当前 OP 权限满足要求。
- 当前格口未处于异常锁定或禁用状态。

### 11.4 格口关闭确认

系统应在开锁后要求确认格口关闭。

如超过配置时间仍未确认关闭：

- 系统应产生告警。
- 系统应禁止 AGV 移动。
- 系统应提示 OP 或管理员处理。

### 11.5 柜体通信异常

当发货柜控制器通信异常时：

- 系统应停止新的开锁操作。
- 系统应阻止 AGV 执行新的移动任务。
- 系统应提示柜体通信异常。
- 系统应记录异常日志。

## 12. RCS 接口需求

### 12.1 接口方式

系统通过 HTTP 访问 RCS。

认证方式应支持：

- 账号密码认证。
- Bearer Token 认证。

系统应支持配置 RCS 地址、认证方式、账号、密码、Token、超时时间和重试次数。

### 12.2 RCS 功能调用

系统应支持调用 RCS 完成：

- 查询 AGV 状态。
- 查询 AGV 当前站点。
- 下发目标站点相关指令。
- 查询移动任务状态。
- 取消移动任务。
- 查询 RCS 接口健康状态。

### 12.3 RCS 状态轮询

系统应通过 HTTP 轮询 RCS 获取任务状态。

系统应处理以下结果：

- 任务已接收。
- AGV 执行中。
- AGV 已到站。
- 任务失败。
- 任务取消。
- AGV 异常。
- RCS 无响应。

### 12.4 RCS 异常处理

当 RCS 返回失败或超时时：

- 系统应记录接口请求和响应。
- 系统应按配置重试。
- 重试仍失败时任务进入异常。
- 系统应提示人工处理。

## 13. MES 接口需求

### 13.1 接口方式

系统通过轮询方式访问 MES。

MES 接口具体协议可为 HTTP API 或现场已有接口形式。需求阶段暂按 HTTP API 方式描述。

### 13.2 MES 任务获取

系统应支持定时轮询 MES 获取待执行任务。

获取任务后应进行：

- 重复任务校验。
- 必填字段校验。
- 物料信息校验。
- 流程模板匹配。
- 任务创建。

### 13.3 MES 状态回传

系统应根据流程模板和任务状态向 MES 回传：

- 任务已接收。
- 装货开始。
- 装货完成。
- AGV 已发车。
- AGV 已到站。
- 取货完成。
- 任务完成。
- 任务异常。
- 任务取消。

具体回传节点应可配置，不同物料和流程可能不同。

### 13.4 MES 校验

部分流程可能需要在装货或取货前与 MES 交互校验。

系统应支持：

- 装货前校验物料是否允许装入。
- 取货前校验 OP 是否允许领取。
- 完成后回传实际执行结果。

是否执行 MES 校验由流程模板决定。

## 14. 用户界面需求

系统应至少支持三类界面：

- 柜端 HMI：运行在发货柜上方电脑或触控屏上，面向现场 OP 存取操作。
- 远程操作端：供 OP 或授权人员远程查看发货柜状态并下发业务指令。
- 管理配置端：供管理员维护基础数据、流程模板、接口参数和权限。

### 14.1 任务看板

系统应提供任务看板，显示：

- 当前任务列表。
- 任务来源。
- 任务状态。
- 当前站点。
- 目标站点。
- 关联格口。
- 异常信息。

### 14.2 AGV 与发货柜状态界面

系统应显示：

- AGV 当前状态。
- AGV 当前站点。
- RCS 连接状态。
- 发货柜连接状态。
- 各格口状态。
- 电子锁状态。
- 传感器状态。

### 14.3 OP 操作界面

OP 操作界面应按流程模板动态显示操作步骤。该界面主要用于发货柜上方电脑，也可在远程操作端复用部分能力。

界面应支持：

- 身份认证。
- 扫码输入。
- 当前任务提示。
- 当前可操作格口提示。
- 操作确认。
- 异常提示。

### 14.4 柜端 HMI

发货柜上方电脑应提供柜端 HMI，用于现场 OP 完成装货、取货和异常确认。

柜端 HMI 应支持：

- 显示当前 AGV 所在站点。
- 显示当前任务和下一步操作提示。
- 显示需要操作的格口编号。
- 显示物料、批次、工单等任务信息。
- 支持 OP 身份认证。
- 支持扫码输入。
- 支持按流程模板引导装货或取货。
- 显示格口电子锁状态。
- 显示格口传感器状态。
- 显示异常原因和处理提示。

柜端 HMI 不应作为主要系统配置入口。流程模板、接口参数、用户权限等高风险配置应在管理配置端完成。

### 14.5 远程操作端

系统应提供远程操作端，供 OP、主管或管理员远程查看发货柜状态并下发授权范围内的业务指令。

远程操作端应支持：

- 查看 AGV 当前站点。
- 查看 AGV 当前状态。
- 查看发货柜在线状态。
- 查看格口状态。
- 查看电子锁状态。
- 查看传感器状态。
- 查看当前任务和历史任务。
- 创建人工任务。
- 请求 AGV 前往指定固定站点。
- 发起取货请求。
- 暂停、取消或处理本人权限范围内的任务。

远程操作端下发开锁类指令时，系统必须执行任务状态、站点状态、AGV 状态、OP 权限和安全联锁校验。普通 OP 不应具备无任务直接远程开锁能力。

管理员或主管执行远程强制开锁时，必须记录操作人、时间、原因、格口、任务关联信息和执行结果。

### 14.6 管理配置界面

系统应提供配置界面，支持维护：

- 用户。
- 角色。
- AGV。
- 发货柜。
- 格口。
- 站点。
- 物料。
- 流程模板。
- MES 接口参数。
- RCS 接口参数。

### 14.7 日志查询界面

系统应支持查询：

- 任务日志。
- 操作日志。
- 开锁日志。
- 扫码日志。
- 身份认证日志。
- MES 接口日志。
- RCS 接口日志。
- 发货柜控制日志。
- 异常日志。

## 15. 异常处理需求

### 15.1 任务异常

任务异常包括：

- 任务数据不完整。
- 无可用格口。
- 物料校验失败。
- OP 权限校验失败。
- 超时未装货。
- 超时未取货。
- RCS 任务失败。
- 发货柜通信失败。
- 电子锁异常。
- 传感器异常。

任务进入异常后，应显示异常原因，并允许授权用户处理。

### 15.2 开锁异常

开锁失败时：

- 系统应提示开锁失败。
- 系统应记录失败原因。
- 系统应允许按配置重试。
- 多次失败后格口进入异常锁定。

### 15.3 传感器异常

传感器异常时：

- 系统应提示传感器状态异常。
- 如果流程模板要求传感器强校验，任务不得继续完成。
- 如果流程模板允许人工确认，授权用户可人工确认并记录原因。

### 15.4 网络异常

网络异常包括：

- MES 不可达。
- RCS 不可达。
- 发货柜控制器不可达。

系统应记录异常，并根据对象不同采取不同策略：

- MES 不可达时，可暂停 MES 任务获取和状态回传。
- RCS 不可达时，不得发起新的 AGV 移动。
- 发货柜不可达时，不得发起新的开锁操作。

### 15.5 断电或服务重启

系统应具备任务恢复能力。

服务重启后应能恢复：

- 未完成任务。
- 格口绑定关系。
- 当前任务状态。
- 最近一次 RCS 任务状态。
- 格口状态。

系统恢复后应重新校验 AGV、RCS、发货柜状态，再允许继续操作。

## 16. 安全联锁需求

系统必须满足以下安全联锁规则：

- AGV 行驶中禁止开锁。
- 格口未关闭禁止 AGV 移动。
- 发货柜通信异常禁止 AGV 移动。
- 任务站点不匹配禁止开锁。
- OP 权限不满足禁止开锁。
- 格口异常锁定禁止普通开锁。
- 强制开锁必须具备权限并记录原因。
- 电子锁状态未知时不得默认认为已关闭。
- 传感器状态未知时不得默认认为物料已正确存取。

## 17. 日志与追溯需求

任务全流程追溯是指系统应能还原一个任务从来源、创建、装货、移动、到站、取货、回传到异常处理的完整过程。系统应记录所有关键行为，形成可查询的证据链。

当发生错料、混批、少料、错领、格口异常、接口异常或人工干预时，系统应能查询到相关任务、物料、批次、工单、格口、OP、接口请求和操作结果。

至少包括：

- 任务创建。
- 任务状态变化。
- MES 请求与响应。
- RCS 请求与响应。
- 发货柜控制请求与响应。
- OP 登录或身份认证。
- 扫码内容和校验结果。
- 开锁请求。
- 开锁结果。
- 格口关闭确认。
- 传感器状态变化。
- AGV 到站状态。
- 任务完成结果。
- 人工干预。
- 异常产生。
- 异常处理。

日志应支持按任务编号、物料编码、批次号、工单号、OP、格口、时间范围查询。

追溯记录应尽量保存当时的实际数据快照，例如任务使用的流程模板版本、MES 原始任务信息、扫码内容、OP 身份、格口绑定关系和接口返回结果，避免后续配置变化影响历史任务复盘。

## 18. 非功能需求

### 18.1 稳定性

系统应支持生产环境连续运行。

核心服务异常重启后，不应丢失未完成任务和格口绑定关系。

### 18.2 可配置性

系统应避免将以下内容写死：

- 格口数量。
- 站点数量。
- 物料单位。
- 扫码规则。
- OP 认证规则。
- MES 回传节点。
- 传感器是否必需。
- 不同物料对应的存取流程。
- 是否允许人工确认或授权放行。

### 18.3 可追溯性

所有与物料、人员、格口、任务、接口、异常相关的关键操作都应可追溯。

### 18.4 易用性

OP 操作界面应尽量按步骤引导，避免让 OP 自行判断复杂状态。

界面提示应明确说明当前需要做什么、不能继续的原因是什么。

### 18.5 权限控制

系统应支持角色权限控制。

高风险操作必须受权限限制，包括：

- 强制开锁。
- 关闭异常任务。
- 修改流程模板。
- 修改接口配置。
- 修改格口配置。

### 18.6 接口容错

MES、RCS、发货柜接口均应具备超时、重试、失败记录能力。

接口失败不得导致任务状态丢失。

## 19. 验收标准

### 19.1 基础配置验收

系统应能完成：

- 配置一台 AGV。
- 配置一个发货柜。
- 配置多个格口。
- 配置每个格口的电子锁地址。
- 配置部分格口是否存在物体检测传感器。
- 配置固定站点。
- 配置流程模板。

### 19.2 MES 任务验收

系统应能：

- 轮询 MES 获取任务。
- 创建内部任务。
- 按任务流程完成装货、移动、取货。
- 回传任务状态给 MES。
- 在 MES 接口异常时记录异常并支持重试。

### 19.3 人工任务验收

系统应能：

- 由授权用户创建人工任务。
- 选择物料和流程模板。
- 完成与 MES 任务一致的执行闭环。

### 19.4 RCS 对接验收

系统应能：

- 通过 HTTP 认证访问 RCS。
- 下发移动任务。
- 轮询移动状态。
- 正确识别 AGV 到站。
- 正确处理 RCS 失败和超时。

### 19.5 发货柜控制验收

系统应能：

- 独立打开指定格口。
- 读取电子锁状态。
- 读取配置了传感器的格口物体状态。
- 禁止非任务格口误开。
- 在格口未关闭时禁止 AGV 移动。

### 19.6 防呆防混批验收

系统应能验证：

- 错误物料无法装入。
- 错误批次无法装入。
- 错误工单无法装入。
- 错误 OP 无法领取受控物料。
- 未到指定站点无法开锁。
- AGV 行驶中无法开锁。

### 19.7 异常恢复验收

系统应能验证：

- RCS 接口失败后任务进入异常。
- 发货柜通信失败后禁止开锁。
- 电子锁异常后格口进入异常锁定。
- 服务重启后未完成任务仍可查询和处理。

## 20. 待确认问题

以下问题需要在后续需求评审中继续确认：

- MES 任务字段的完整定义。
- MES 回传接口字段和回传节点。
- RCS 接口的具体 URL、认证方式、请求体和响应体。
- 发货柜控制器通信协议。
- 电子锁状态反馈能力。
- 传感器状态反馈周期和可靠性。
- OP 身份认证方式，例如刷卡、工号密码、扫码或对接厂内账号系统。
- 条码规则，包括物料码、批次码、工单码、取货凭证码。
- 不同物料类型对应的首批流程模板清单。
- 固定站点数量和站点编码。
- 一期是否需要支持任务优先级。
- 一期是否需要支持任务取消后自动回传 MES。
