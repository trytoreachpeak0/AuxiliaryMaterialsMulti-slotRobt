# 任务管理层 Task Management Layer

## 1. 文档说明

### 1.1 文档目的

任务管理层负责接收、创建、转换、匹配、编排和追踪复合机器人发货柜系统中的业务任务，并维护任务从创建到完成、异常或关闭的生命周期。

任务管理层应向上衔接 MES 任务、人工创建任务和管理端操作，向下协调流程模板层、机器人任务层、站点作业层和日志追溯能力。

本文档用于说明任务管理层在需求阶段需要具备的任务对象、任务来源、业务运行模式、任务状态机、任务拆分与合并、模板绑定、执行编排、异常处理和追溯要求，不描述具体数据库表结构、接口报文格式、前端页面实现或代码实现方式。

### 1.2 职责边界

任务管理层负责“任务是什么、任务怎么流转、任务当前执行到哪里”。

简单来说：

- MES 接口层负责“从 MES 获取任务、向 MES 回传结果”。
- 人工界面负责“采集人工创建任务所需信息”。
- 任务管理层负责“统一任务模型、任务状态机、流程模板绑定和执行顺序”。
- 机器人任务层负责“根据任务要求调用 RCS 让 AGV 到达目标站点”。
- 站点作业层负责“AGV 到站后 OP 怎么装货、取货、确认和异常处理”。
- 流程模板层负责“不同业务模式和物料规则下任务应该采用哪些流程配置”。
- 格口控制层负责“被授权后的格口开锁和状态查询”。

任务管理层不直接控制 AGV 底盘运动，不直接驱动电子锁，也不直接决定 OP 是否能开某个格口。任务管理层只维护任务生命周期和执行编排，并调用对应下层能力。

### 1.3 一期建设原则

一期任务管理层应优先支持单车单柜、固定站点、有限业务模式下的稳定任务闭环。

当前业务运行模式可先归纳为三类：

- 驻点发料：复合机器人发货柜到达指定站点后长期停留，等待多个 OP 按任务或权限分别领取不同物料。
- 多点配送：复合机器人发货柜在一个地点完成上料后，依次前往多个指定机台、产线或站点完成卸货或发料。
- 多点收料：复合机器人发货柜依次前往多个机台、产线或站点收料，再送到一个指定地点统一下料。

任务管理层应支持不同业务运行模式使用统一任务模型和统一状态追踪方式，避免为每种业务模式建立完全独立的任务体系。

## 2. 控制对象

### 2.1 任务 Task

任务是系统执行物料发放、配送、回收、退回、补料或人工操作的业务载体。

任务至少包含：

- 任务编号。
- 任务来源。
- 任务类型。
- 业务运行模式。
- 当前任务状态。
- 优先级。
- 关联流程模板编号。
- 关联流程模板版本。
- 起始站点。
- 目标站点或目标站点列表。
- 当前站点。
- 关联复合机器人编号。
- 关联发货柜编号。
- 关联任务明细。
- 创建时间。
- 开始时间。
- 完成时间。
- 异常原因，如果有。

任务进入执行前，应绑定流程模板版本，并记录模板快照，避免流程模板后续修改影响正在执行或历史任务。

### 2.2 任务明细 Task Detail

任务明细表示任务中具体需要装入、发放、配送、回收或下料的物料项。

任务明细至少包含：

- 明细编号。
- 关联任务编号。
- 物料编码。
- 物料名称。
- 物料类型。
- 批次。
- 工单。
- 数量。
- 单位。
- 来源站点。
- 目标站点。
- 目标格口或候选格口。
- 存货 OP。
- 领货 OP。
- 明细状态。
- MES 关联字段，如果有。

一个任务可包含多个任务明细。多点配送和驻点发料场景中，不同任务明细可对应不同目标站点、不同格口和不同领货 OP。

### 2.3 业务运行模式 Business Mode

业务运行模式用于描述任务整体执行方式。

一期建议支持：

- 驻点发料。
- 多点配送。
- 多点收料。

业务运行模式应影响任务执行编排、站点顺序、补料策略、取货策略、充电返回策略和异常处理方式。

### 2.4 任务来源 Task Source

任务来源表示任务进入系统的方式。

任务来源至少包括：

- MES 任务：系统通过 MES 接口轮询或接收。
- 人工任务：授权用户通过界面创建。
- 系统任务：系统因充电、返回驻点、补料、异常恢复等内部原因生成的辅助任务或动作。

不同任务来源应转换为统一内部任务模型，并按统一任务状态机管理。

### 2.5 站点执行计划 Station Execution Plan

站点执行计划表示任务需要经过哪些站点以及在每个站点执行什么阶段。

站点执行计划至少包含：

- 任务编号。
- 执行顺序。
- 站点编号。
- 站点类型。
- 阶段类型，例如装货、运输、驻点等待、取货、收料、卸货、充电、异常处理。
- 关联任务明细。
- 计划状态。
- 实际到站时间。
- 实际离站时间。

站点执行计划由任务管理层根据任务数据、业务运行模式、流程模板和站点配置生成。机器人任务层根据站点执行计划调用 RCS 到达指定固定站点。

## 3. 任务来源需求

### 3.1 MES 任务接收

系统应支持从 MES 获取任务，并转换为内部统一任务模型。

MES 任务至少应包含或可映射出：

- MES 任务编号。
- 任务类型。
- 物料信息。
- 批次或工单信息。
- 数量。
- 起始站点。
- 目标站点或目标站点列表。
- 业务运行模式，如果 MES 提供。
- 需要回传的业务字段。

MES 任务接收后，任务管理层应完成字段校验、去重判断、流程模板匹配和任务创建。

### 3.2 人工任务创建

系统应支持授权用户通过界面创建人工任务。

人工创建任务时至少应支持填写或选择：

- 任务类型。
- 业务运行模式。
- 物料信息。
- 数量。
- 起始站点。
- 目标站点或目标站点列表。
- 目标格口规则。
- 流程模板或模板匹配条件。
- 备注或原因。

人工任务应与 MES 任务使用统一任务模型和状态机。

### 3.3 系统辅助任务

系统可根据运行需要生成辅助任务或内部动作。

包括：

- 低电量返回充电。
- 充电完成返回原驻点。
- OP 呼叫补料后返回物料间。
- 异常解除后返回指定站点。
- 空闲返回等待站点。

系统辅助任务不应绕过主任务的安全联锁、格口状态检查和任务追溯要求。

## 4. 任务创建与模板绑定

### 4.1 任务创建校验

任务创建时至少应校验：

- 任务编号是否唯一。
- 任务来源是否合法。
- 任务类型是否支持。
- 业务运行模式是否支持。
- 物料信息是否完整。
- 起始站点和目标站点是否存在且启用。
- 任务是否能匹配到可用流程模板。
- 是否存在重复任务或冲突任务。

校验失败时，系统不得创建可执行任务，应提示失败原因并记录日志。

### 4.2 流程模板匹配

任务管理层应在任务创建或进入执行前匹配流程模板。

匹配条件可包括：

- 业务运行模式。
- 任务类型。
- 任务来源。
- 物料类型。
- 物料编码。
- 起始站点类型。
- 目标站点类型。
- MES 校验要求。
- OP 绑定要求。
- 传感器确认要求。

匹配成功后，任务应记录模板编号、模板版本和模板快照。匹配失败或匹配冲突时，任务不得进入执行。

### 4.3 任务明细生成

任务创建后，系统应根据任务内容生成任务明细。

对于多物料、多目标站点或多 OP 取料任务，系统应支持一个任务包含多个任务明细。

任务明细应能独立记录当前状态、目标格口、存货 OP、领货 OP、完成时间和异常原因。

## 5. 任务状态定义

### 5.1 主任务状态

任务状态建议包括：

- 待创建：外部任务已接收但尚未完成内部创建。
- 待执行：任务已创建并完成模板绑定，等待执行条件满足。
- 执行中：任务正在执行。
- 等待到站：AGV 正在前往任务站点或等待 RCS 到站反馈。
- 等待作业：AGV 已到站，等待 OP 或站点作业层处理。
- 驻点等待：驻点发料模式下，发货柜停留在指定站点等待 OP 取料。
- 等待补料：驻点发料模式下，已触发补料需求但尚未完成补料。
- 充电中：因低电量进入充电流程。
- 异常中：任务发生异常，等待处理。
- 已完成：任务全部明细和站点作业完成。
- 已取消：任务在执行前或执行中被授权取消。
- 已关闭：任务由管理员或系统按规则关闭。

### 5.2 任务明细状态

任务明细状态建议包括：

- 待分配格口。
- 待装货。
- 装货中。
- 已装货。
- 运输中。
- 待取货。
- 取货中。
- 已取货。
- 待收料。
- 收料中。
- 已收料。
- 待下料。
- 下料中。
- 已下料。
- 异常。
- 已取消。

### 5.3 状态流转原则

任务状态流转应由任务管理层统一维护。

站点作业层、机器人任务层、MES 接口层和格口控制层可向任务管理层上报执行结果或异常事件，由任务管理层根据当前状态和业务规则更新任务状态。

系统不得允许任务跳过必要状态直接完成。例如未完成装货确认、未完成格口关闭确认或未完成取货确认时，不得将任务标记为完成。

## 6. 业务运行模式

### 6.1 驻点发料任务

驻点发料任务表示复合机器人发货柜到达指定发料站点后长期停留，供多个 OP 分别领取不同物料。

基本流程：

1. 任务创建并绑定驻点发料流程模板。
2. 如需补料，复合机器人前往物料间或上料点完成装货。
3. 复合机器人到达指定发料站点。
4. 任务进入驻点等待状态。
5. 不同 OP 根据任务、权限、扫码或凭证领取对应物料。
6. 每次取料完成后记录实际领货 OP，并按模板回传 MES。
7. 物料不足或 OP 呼叫补料时，任务进入等待补料或补料流程。
8. 低电量时返回充电点。
9. 充电完成后返回原驻点继续发料。

驻点发料模式下，除低电量、异常处理或 OP/授权人员呼叫补料外，系统不应自动返回物料间补料。

### 6.2 多点配送任务

多点配送任务表示在一个上料点装货后，按计划前往多个目标站点完成卸货或发料。

基本流程：

1. 任务创建并绑定多点配送流程模板。
2. 复合机器人前往上料点。
3. OP 按模板完成装货。
4. 系统生成多个目标站点执行计划。
5. 复合机器人依次前往目标站点。
6. 每到一个目标站点，站点作业层按模板执行取货或卸货作业。
7. 每个站点完成后记录结果，并按模板回传 MES。
8. 全部目标站点完成后，任务完成或进入返回/等待状态。

多点配送模式下，每个目标站点只能操作与当前站点、当前任务明细和当前 OP 权限匹配的格口。

### 6.3 多点收料任务

多点收料任务表示复合机器人依次到多个机台、产线或站点收取物料，再送到一个指定地点统一下料。

基本流程：

1. 任务创建并绑定多点收料流程模板。
2. 系统生成多个收料站点执行计划。
3. 复合机器人依次前往各收料站点。
4. 每到一个收料站点，OP 按模板完成存料或收料作业。
5. 每次收料完成后记录实际存货 OP、来源站点、物料和格口。
6. 全部收料站点完成后，复合机器人前往统一下料点。
7. OP 或仓库人员按模板完成下料。
8. 下料结果按模板记录或回传 MES。

多点收料模式下，任一收料站点异常时，系统应根据模板配置决定重试、等待人工处理、跳过该站点或终止任务。

## 7. 机器人任务协同

### 7.1 目标站点下发

任务管理层应根据任务状态和站点执行计划，向机器人任务层提出目标站点请求。

机器人任务层负责调用 RCS，使 AGV 到达指定固定站点。

任务管理层不负责 AGV 如何行驶、路径规划、避障或交通管制。

### 7.2 到站处理

机器人任务层收到到站结果后，应通知任务管理层。

任务管理层应根据当前任务、当前站点和流程模板判断是否创建或推进站点作业会话。

如果 AGV 到达站点与任务计划不一致，任务管理层不得允许普通作业继续，应进入异常或等待处理。

### 7.3 充电与返回

系统应支持低电量返回充电。

驻点发料模式下，低电量返回充电前应确认：

- 当前无正在开锁或正在操作的格口。
- 所有格口已关闭或锁状态可信。
- 当前站点作业已完成或已安全挂起。

充电完成后，若原驻点任务仍有效，系统应返回原驻点继续发料。

## 8. 与站点作业层的关系

任务管理层负责创建站点作业会话或触发站点作业层处理当前站点作业。

站点作业层完成装货、取货、收料、下料、确认或异常处理后，应向任务管理层回写结果。

任务管理层根据站点作业结果更新任务状态、任务明细状态、站点执行计划和后续目标站点。

## 9. 异常处理需求

### 9.1 任务异常类型

任务异常可包括：

- MES 任务解析失败。
- 流程模板匹配失败。
- 任务数据缺失。
- 站点不存在或禁用。
- 目标站点不可达。
- RCS 下发失败。
- AGV 未按计划到站。
- 站点作业失败。
- 格口状态异常。
- OP 权限异常。
- MES 回传失败。
- 低电量中断任务。

### 9.2 异常处理原则

任务异常发生后，系统应记录异常原因、发生阶段、影响任务、影响明细和处理建议。

异常处理方式可包括：

- 自动重试。
- 等待人工处理。
- 跳过当前站点或明细。
- 重新派发目标站点。
- 进入充电后恢复。
- 管理员关闭任务。
- 回传 MES 异常状态。

高风险异常不得自动忽略，例如格口未关闭、站点不匹配、非授权 OP 取料、防错料校验失败等。

## 10. 日志与追溯需求

任务管理层应记录任务全生命周期日志。

至少包括：

- 任务创建日志。
- 任务来源和原始任务编号。
- 流程模板匹配结果。
- 任务状态变更日志。
- 任务明细状态变更日志。
- 站点执行计划变更日志。
- RCS 目标站点下发记录。
- 到站和离站记录。
- OP 装货、取货、收料、下料结果。
- MES 回传结果。
- 充电返回和充电完成返回驻点记录。
- OP 呼叫补料记录。
- 异常处理记录。

系统应支持按任务编号、MES 任务编号、物料、批次、OP、站点、格口、时间范围查询任务追溯信息。

## 11. 非功能需求

### 11.1 一致性

任务状态、任务明细状态、站点执行计划和格口业务状态应保持一致。

当下层执行失败时，任务管理层不得错误推进任务完成。

### 11.2 可恢复性

系统重启或通信恢复后，应能根据任务状态、站点执行计划、格口状态和日志恢复任务执行上下文。

对于驻点发料任务，应能恢复原驻点、库存格口、已取明细、待取明细和是否需要补料。

### 11.3 可追溯性

任务执行过程中的关键决策都应可追溯，包括模板匹配、站点选择、格口绑定、OP 操作、MES 回传和异常处理。

### 11.4 可扩展性

任务管理层应允许后续扩展新的业务运行模式、任务来源、任务类型和站点阶段，但不应破坏一期已定义的统一任务模型和状态机。

## 12. 待确认问题

以下内容需要在详细设计或现场调研阶段进一步确认：

- MES 是否会直接提供业务运行模式，还是由系统根据任务字段匹配。
- 驻点发料模式下补料触发条件是否只有 OP 呼叫，是否还包含库存低于阈值。
- 驻点发料模式下多个 OP 同时请求取料时的排队规则。
- 多点配送任务的站点顺序由 MES 指定、人工指定，还是系统排序。
- 多点收料任务是否允许某个站点失败后继续执行后续站点。
- 低电量阈值、充电完成阈值和返回原驻点策略。
- 人工任务是否允许手动选择流程模板，还是必须自动匹配。
