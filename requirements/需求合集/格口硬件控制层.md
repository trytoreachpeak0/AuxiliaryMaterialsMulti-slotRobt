# 格口硬件控制层 Slot Hardware Control Layer

## 1. 文档说明

### 1.1 文档目的

格口硬件控制层负责对接发货柜内部 IO 模块、电子锁、门状态反馈和物体检测传感器，向格口控制层提供稳定的硬件访问能力。

本层应支持 IO 模块连接管理、电子锁开锁指令、锁状态读取、门状态读取、物体检测传感器状态读取、通信状态检测、硬件异常识别和异常反馈。

本文档用于说明格口硬件控制层在需求阶段需要具备的硬件对象、通信状态、控制指令、状态读取、异常反馈和追溯要求，不描述具体 Modbus 地址表、寄存器定义、电气接线图或驱动代码实现。

### 1.2 职责边界

格口硬件控制层负责“和硬件通信，并返回真实可用的硬件结果”。

简单来说：

- 站点作业层决定“业务上是否允许开格口”。
- 格口控制层决定“要操作哪个格口，以及如何解释格口业务状态”。
- 格口硬件控制层负责“通过 IO 模块发送开锁指令，读取电子锁、门状态和传感器反馈”。
- IO 模块、电子锁和传感器负责“实际执行动作并提供电气信号”。

格口硬件控制层不判断 OP 是否有权限，不判断任务是否匹配，也不直接改变库存数据。

### 1.3 一期建设原则

一期应优先保证开锁可靠、状态可见、异常可追溯。

一期至少应支持：

- 多块 IO 模块配置。
- 每个格口与 IO 模块地址、开锁输出点、状态输入点的映射。
- 指定格口开锁。
- 批量读取锁状态或门状态。
- 批量读取物体检测传感器状态。
- 通信断开、超时、返回异常和状态不一致识别。
- 硬件异常向上反馈。

## 2. 硬件对象

### 2.1 硬件连接架构 Hardware Architecture

本项目格口硬件控制层一期采用“触控屏电脑 + IO 模块 + 电子锁/传感器”的硬件架构。

硬件连接关系如下：

- 触控屏电脑运行上位机系统和格口硬件控制层服务。
- 触控屏电脑与 IO 模块之间通过 Modbus TCP 通信。
- IO 模块的 DO 输出点连接电子锁，用于执行开锁动作。
- IO 模块的 DI 输入点连接锁状态反馈、门状态反馈和物体检测传感器。
- 格口硬件控制层不直接驱动电子锁和传感器电气信号，而是通过 IO 模块完成输出控制和输入采集。

### 2.2 IO 模块 IO Module

IO 模块是连接触控屏电脑与格口电子锁、传感器的硬件控制模块。

IO 模块至少包含：

- IO 模块编号。
- 所属发货柜编号。
- 通信类型，一期为 Modbus TCP。
- 通信地址，例如 IP 和端口。
- DO 输出模式能力，例如是否支持电平模式、硬件脉冲模式。
- DO 脉冲参数读写能力。
- 通信状态。
- 关联 IO 点位清单。
- 硬件配置启用/禁用状态。

每个 IO 模块应对应一份关联 IO 点位清单，用于描述该模块上实际接入的 DO 输出点和 DI 输入点。

系统应支持一个发货柜配置多块 IO 模块。不得假设 IO 模块与格口之间存在连续范围关系，应以 IO 映射配置为准。

### 2.3 电子锁 Electric Lock

电子锁是安装在每个格口上的开锁执行部件。

电子锁至少包含：

- 关联格口编号。
- 所属 IO 模块。
- 开锁 DO 输出点位。
- 开锁输出模式，例如硬件脉冲、软件脉冲或电平输出。
- 锁状态 DI 输入点位，如果有。
- 门状态 DI 输入点位，如果有。
- 软件脉冲启用状态。
- 软件脉冲时长。
- 硬件脉冲期望时长。
- 开锁超时时间。
- 硬件配置启用/禁用状态。

系统通常只能控制开锁，不能主动关门。关门动作由 OP 手动完成，系统负责读取反馈并判断是否恢复正常。

### 2.4 传感器 Sensor

传感器用于读取格口内物体状态、门状态或其他硬件状态。

传感器类型可包括：

- 物体检测传感器。
- 门状态传感器。
- 锁状态反馈。
- IO 模块故障输入。

传感器至少包含：

- 传感器编号。
- 关联格口编号，如果适用。
- 所属 IO 模块。
- DI 输入点位或寄存器地址。
- 信号有效值。
- 硬件配置是否启用。
- 最近一次读取时间。

物体检测传感器结果可能受物料尺寸、位置和检测范围影响。是否强制依赖传感器确认，应由流程模板和格口控制层共同决定。

### 2.5 IO 映射 IO Mapping

IO 映射用于描述格口与 IO 模块硬件点位之间的关系。

IO 映射至少包含：

- 格口编号。
- IO 模块编号。
- 开锁 DO 输出地址。
- 开锁 DO 输出模式。
- 开锁 DO 软件脉冲启用状态。
- 开锁 DO 软件脉冲时长。
- 开锁 DO 硬件脉冲期望时长。
- 锁状态 DI 输入地址，如果有。
- 门状态 DI 输入地址，如果有。
- 物体检测 DI 输入地址，如果有。
- 地址硬件配置启用状态。
- 配置版本。

IO 映射应以格口编号作为主关联对象。物理位置可作为界面展示、现场接线核对和维护辅助信息，但不应作为硬件控制的唯一依据。

开锁输出模式和软件脉冲参数应配置在具体开锁 DO 点位上，不应只配置在 IO 模块级别。IO 模块级别只描述该模块支持哪些输出能力，具体某个格口开锁时采用硬件脉冲、软件脉冲还是电平输出，应以该格口对应的开锁 DO 点位配置为准。

IO 映射属于高风险配置。修改后应记录修改人、修改时间、修改前后内容和生效范围。

### 2.6 硬件启用/禁用与业务启用/禁用关系

格口硬件控制层中的启用/禁用只表示硬件对象或点位配置是否可用，例如 IO 模块、DO 输出点、DI 输入点、电子锁和传感器是否参与硬件控制与状态读取。

格口控制层中的格口启用/禁用表示业务可用性，用于决定格口是否允许参与任务分配、普通业务开锁和作业流程。

两者的职责边界如下：

- 硬件层启用/禁用不直接改变格口业务启用/禁用状态。
- 硬件层发现硬件对象禁用、未配置或不可用时，应向格口控制层返回明确硬件原因。
- 格口控制层负责结合业务启用状态、硬件状态、任务占用、异常锁定和安全联锁，最终判断格口是否允许业务操作。

业务启用/禁用与硬件启用/禁用组合后的含义如下：

- 业务启用且硬件启用：格口具备参与普通业务的基础条件，仍需继续检查通信、锁状态、门状态、任务占用和流程规则。
- 业务启用但硬件禁用：格口业务上允许使用，但当前缺少可用硬件控制或状态读取能力，应阻止普通业务开锁，并提示硬件配置不可用。
- 业务禁用但硬件启用：硬件可通信和控制，但格口被业务或维护策略停用，不应参与任务分配或普通业务开锁；可按权限执行维护检查。
- 业务禁用且硬件禁用：格口同时处于业务停用和硬件不可用状态，应等待维护、重新配置或人工确认后再恢复。

## 3. 通信状态

### 3.1 IO 模块通信状态

IO 模块通信状态用于判断系统是否能正常读取和控制硬件。通信状态应包含周期通信检测结果，不再单独维护心跳状态。

建议状态包括：

- 未配置。
- 未连接。
- 已连接。
- 通信正常。
- 请求超时。
- 返回异常。
- 通信中断。
- 硬件配置禁用。

当 IO 模块通信异常时，关联到该 IO 模块点位的格口不得执行普通业务开锁。

### 3.2 点位读取状态

点位读取状态用于判断某个输入或输出地址是否可用。

建议状态包括：

- 正常。
- 读取失败。
- 写入失败。
- 地址未配置。
- 地址冲突。
- 返回值非法。

若一个格口的关键点位未配置或读取失败，应向格口控制层返回明确异常原因。

## 4. 控制指令

### 4.1 开锁指令

格口硬件控制层应支持对指定格口发送开锁指令。

开锁指令至少包含：

- 指令编号。
- 格口编号。
- IO 模块编号。
- 开锁 DO 输出地址。
- 开锁 DO 输出模式。
- 软件脉冲时长，如果使用软件脉冲模式。
- 硬件脉冲期望时长，如果使用硬件脉冲模式。
- 请求来源。
- 关联业务任务编号。
- 操作人，如果有。
- 指令下发时间。

开锁前应进行硬件级校验：

- IO 模块通信正常。
- 开锁 DO 输出地址已配置。
- 开锁 DO 输出模式已配置。
- 若使用硬件脉冲模式，应确认 IO 模块中该 DO 已开启脉冲模式且脉冲时长符合配置要求。
- 若使用软件脉冲模式，应确认该开锁 DO 的软件脉冲已启用且软件脉冲时长已配置。
- 当前无同一格口未完成开锁指令。
- IO 模块未处于硬件配置禁用或故障状态。

硬件层只校验硬件条件，不替代业务权限校验。

开锁输出模式应支持：

- 硬件脉冲模式：IO 模块内部已配置 DO 为脉冲输出。开锁时软件只需向对应 DO 写入 1 或 True，由 IO 模块按已配置脉冲时长自动输出并复位。
- 软件脉冲模式：IO 模块 DO 处于普通电平输出模式。开锁时软件先向对应 DO 写入 1 或 True，等待该 DO 点位配置的软件脉冲时长后，再写入 0 或 False。
- 电平输出模式：软件直接控制 DO 输出电平，仅在调试、特殊硬件或明确业务需要时使用。

软件脉冲模式应按开锁 DO 点位配置是否启用和脉冲时长。同一 IO 模块上的不同 DO 点位可以采用不同开锁输出模式。若使用硬件脉冲模式，不应再叠加软件脉冲复位逻辑，避免同一开锁动作被重复或异常触发。

### 4.2 开锁执行结果

开锁执行结果应区分“指令写入成功”和“格口实际状态变化”。

建议结果包括：

- 指令已发送。
- 指令发送失败。
- 输出写入成功。
- 输出写入失败。
- 等待反馈。
- 反馈确认成功。
- 反馈超时。
- 状态不一致。

如果硬件没有锁状态或门状态反馈，系统至少应记录指令写入结果，并向上层说明无法硬件确认实际开锁状态。

### 4.3 DO 脉冲参数检查与设置

格口硬件控制层应具备对 IO 模块 DO 脉冲参数进行检查的能力。

检查内容至少包括：

- 指定 DO 是否支持脉冲模式。
- 指定 DO 当前是否已开启脉冲模式。
- 指定 DO 当前脉冲时长是否与系统配置一致。
- 指定 DO 当前输出模式是否与该格口开锁输出模式一致。

若 IO 模块协议支持写入配置，格口硬件控制层应支持对指定 DO 设置输出模式和脉冲时长。设置后应重新读取并确认实际生效结果。

若 IO 模块不支持读取或写入脉冲参数，系统应将该能力标记为不支持，并在配置校验或开锁前返回明确提示，不应默认认为硬件脉冲参数正确。

### 4.4 状态读取指令

格口硬件控制层应支持读取单个格口状态，也应支持批量读取所有格口状态。

读取内容可包括：

- 锁状态。
- 门状态。
- 物体检测状态。
- IO 模块通信状态。
- 点位读取状态。

批量读取用于界面展示、安全联锁和任务调度判断。

## 5. 状态读取与解释

### 5.1 锁状态

锁状态用于表示电子锁机构反馈。

建议状态包括：

- 已锁。
- 已释放。
- 未配置反馈。
- 读取失败。
- 状态未知。

锁状态关注锁机构本身，不等同于门是否打开或关闭。

### 5.2 门状态

门状态用于表示格口门是否打开或关闭。

建议状态包括：

- 已关闭。
- 已打开。
- 未配置反馈。
- 读取失败。
- 状态未知。

若当前硬件没有独立门状态检测，应明确返回未配置反馈，不应伪造门状态。

### 5.3 物体检测状态

物体检测状态用于表示格口内是否检测到物体。

建议状态包括：

- 有物。
- 无物。
- 未配置传感器。
- 读取失败。
- 状态未知。

物体检测结果不应直接等同于库存事实。库存事实仍应由任务、扫码、OP 确认和传感器结果共同形成。

## 6. 异常反馈

### 6.1 通信异常

通信异常包括：

- IO 模块连接失败。
- 请求超时。
- 周期通信检测失败。
- 返回数据格式异常。
- 连接频繁断开。

通信异常应影响所有关联到该 IO 模块点位的格口可操作性，并向界面层展示清晰告警。

### 6.2 开锁异常

开锁异常包括：

- 开锁输出点未配置。
- 开锁输出模式未配置或不支持。
- 硬件脉冲模式未开启。
- 硬件脉冲时长与配置不一致。
- 写入开锁指令失败。
- 开锁后锁状态未变化。
- 开锁反馈超时。
- 同一格口重复开锁冲突。

开锁异常应返回格口编号、IO 模块编号、异常原因和建议处理方式。

### 6.3 状态不一致

状态不一致包括：

- 指令写入成功但锁状态未变化。
- 门状态显示打开但锁状态显示已锁。
- 门状态显示关闭但锁状态未恢复。
- 传感器结果与业务预期不一致。

状态不一致应上报格口控制层，由格口控制层结合业务状态判断是否需要禁用格口、要求人工确认或允许继续。

### 6.4 配置异常

配置异常包括：

- 格口未配置 IO 模块。
- 点位地址缺失。
- 多个格口使用同一输出地址。
- 开锁 DO 输出模式配置缺失或不一致。
- 硬件脉冲参数无法读取、无法设置或与配置不一致。
- 地址范围不合法。
- IO 模块未启用。

配置异常应在系统启动或配置保存时尽量提前发现，不应等到现场开锁时才暴露。

## 7. 日志与追溯

格口硬件控制层应记录：

- IO 模块连接、断开和周期通信检测异常日志。
- 开锁指令请求、写入结果和反馈结果。
- DO 输出模式和脉冲参数检查、设置结果。
- 状态读取失败、超时和返回异常。
- 传感器状态变化。
- IO 映射配置变更。
- 硬件异常上报和解除记录。

日志至少应包含格口编号、IO 模块编号、点位地址、指令编号、关联任务编号、操作人、操作时间和执行结果。
