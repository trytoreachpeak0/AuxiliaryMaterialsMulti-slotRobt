# 流程模板层 Process Template Layer

## 1. 文档说明

### 1.1 文档目的

流程模板层负责定义不同任务类型、物料类型、任务来源和业务场景下的作业步骤、校验规则、权限要求、异常处理方式和界面提示规则。

流程模板层不直接执行任务、不直接操作格口、不直接调用 MES 或 RCS，也不直接控制界面显示。流程模板层向任务管理层、站点作业层和界面层提供可读取、可版本化、可追溯的流程规则。

本文档用于说明流程模板层在需求阶段需要具备的模板对象、配置项、匹配规则、版本管理、执行约束、典型模板和追溯要求，不描述具体数据库表结构、前端页面实现、接口报文格式或代码实现方式。

### 1.2 职责边界

流程模板层负责“不同业务流程差异的定义和管理”。

简单来说：

- 任务管理层负责“任务从创建到完成的生命周期”。
- 流程模板层负责“不同任务应该采用什么作业规则”。
- 站点作业层负责“AGV 到站后按照模板执行 OP 作业流程”。
- 格口控制层负责“在被授权后执行格口开锁和状态查询”。
- 界面层负责“展示当前步骤、提示 OP 操作并采集输入”。

流程模板层不应替代任务状态机，也不应替代站点作业层的业务执行逻辑。流程模板只定义规则和步骤要求，站点作业层负责在运行时解释这些规则并驱动作业状态流转。

### 1.3 一期建设原则

一期流程模板应采用有限配置项方式实现，不要求建设完全自由编排的流程引擎。

一个流程模板应对应一种完整任务或业务流程，并包含该流程中各阶段的配置，例如装货阶段、运输或送货阶段、取货或卸货阶段、异常处理阶段等。系统不建议将装货、送货、卸货拆成彼此独立的多个流程模板，否则会增加任务绑定、版本追溯和跨阶段规则一致性的复杂度。

当前业务运行模式可先归纳为三类：

- 驻点发料：复合机器人发货柜到达指定站点后长期停留，等待多个 OP 按任务或权限分别领取不同物料。
- 多点配送：复合机器人发货柜在一个地点完成上料后，依次前往多个指定机台、产线或站点完成卸货或发料。
- 多点收料：复合机器人发货柜依次前往多个机台、产线或站点收料，再送到一个指定地点统一下料。

业务运行模式是流程模板的一级分类。普通辅料、受控物料、MES 强校验、传感器强校验等规则，可作为三类业务运行模式下的具体模板差异。例如系统可以配置“驻点发料-受控物料流程”、“多点配送-MES 强校验流程”或“多点收料-普通辅料流程”。

一期应优先支持现场明确需要的配置项，例如：

- 是否需要 OP 认证。
- 是否需要扫码。
- 扫码字段要求。
- 是否需要 MES 校验。
- 是否需要传感器确认。
- 是否允许人工确认。
- 是否绑定存货 OP 或领货 OP。
- 是否允许代取。
- 是否允许混批或同格口多物料。
- 是否允许主管或管理员放行。
- 超时和异常处理方式。
- 界面提示内容。

系统不得通过修改界面逻辑来改变核心业务流程。不同流程差异应通过流程模板配置体现，并由站点作业层统一执行。

## 2. 控制对象

### 2.1 流程模板 Process Template

流程模板是描述一类任务在装货、运输、取货、确认和异常处理过程中需要执行哪些规则的配置对象。

流程模板至少包含：

- 模板编号。
- 模板名称。
- 模板类型。
- 模板版本。
- 业务运行模式。
- 启用/禁用状态。
- 适用任务类型。
- 适用任务来源。
- 适用物料类型。
- 适用站点类型。
- 装货阶段配置。
- 运输或送货阶段配置。
- 取货或卸货阶段配置。
- 异常处理配置。
- MES 交互配置。
- 界面提示配置。
- 创建人、创建时间、修改人、修改时间。

流程模板一旦被任务引用，应保留当时的模板版本，用于后续执行和追溯。

### 2.2 模板版本 Template Version

模板版本表示流程模板在某一时间点的完整规则快照。

系统应支持流程模板版本管理。模板修改后，应形成新的版本或更新版本号，并只影响后续新创建任务。

已经创建、正在执行或已完成的任务，应继续使用任务创建时绑定的模板版本，不得因为模板后续修改而改变历史任务执行规则。

模板版本至少应记录：

- 模板编号。
- 版本号。
- 版本状态，例如草稿、启用、停用、历史。
- 生效时间。
- 失效时间，如果有。
- 发布人。
- 发布时间。
- 变更说明。

### 2.3 模板适用条件 Template Matching Condition

模板适用条件用于判断某个任务应绑定哪个流程模板。

模板适用条件可包括：

- 任务类型，例如装货、取货、配送、退回、人工配送。
- 业务运行模式，例如驻点发料、多点配送、多点收料。
- 任务来源，例如 MES、人工创建。
- 物料类型，例如普通辅料、受控物料、贵重物料、需校验物料。
- 物料编码或物料分类。
- 起始站点类型。
- 目标站点类型。
- 是否需要 MES 强校验。
- 是否需要 OP 绑定。
- 是否需要传感器强确认。

当多个模板同时匹配时，系统应按照明确优先级选择模板。若无法唯一确定模板，应拒绝创建或启动任务，并提示需要维护模板配置。

### 2.4 流程步骤 Flow Step

流程步骤表示模板中可被站点作业层执行的单个业务动作或校验动作。

一期流程步骤可包括：

- OP 身份认证。
- 扫码。
- 本地业务校验。
- MES 校验。
- 格口操作授权。
- 开格口。
- 等待 OP 装货。
- 等待 OP 取货。
- 驻点等待 OP 取货。
- OP 呼叫补料。
- 低电量返回充电。
- 充电完成返回驻点。
- 传感器确认。
- 人工确认。
- 关门或锁状态确认。
- MES 结果回传。
- 异常处理。
- 主管或管理员放行。

流程步骤的执行顺序不要求完全自由配置，但系统应支持通过模板配置决定某些步骤是否启用、需要校验哪些字段、失败后如何处理。

### 2.5 模板快照 Template Snapshot

模板快照表示任务实际使用的模板规则副本。

系统创建任务或任务进入执行前，应记录任务绑定的模板编号、版本号和关键配置快照。模板快照用于保证任务执行过程稳定，并满足历史追溯要求。

模板快照至少应包含：

- 任务编号。
- 模板编号。
- 模板名称。
- 模板版本。
- 绑定时间。
- 绑定原因或匹配条件。
- 装货阶段关键配置。
- 取货阶段关键配置。
- 异常处理关键配置。
- MES 交互关键配置。

## 3. 模板配置需求

### 3.1 基础配置

流程模板应支持以下基础配置：

- 模板编号。
- 模板名称。
- 模板描述。
- 模板分类。
- 模板版本。
- 业务运行模式。
- 启用/禁用状态。
- 是否系统预置。
- 是否允许修改。
- 适用任务类型。
- 适用任务来源。
- 适用物料类型。
- 默认优先级。

禁用模板不得用于新任务创建，但已经绑定该模板版本的历史任务仍应可查询和追溯。

### 3.2 装货阶段配置

装货阶段配置用于控制 OP 在装货站点执行装货时需要完成哪些步骤。

装货阶段至少应支持：

- 是否允许装货。
- 是否需要 OP 身份认证。
- 是否需要指定角色 OP。
- 是否绑定存货 OP。
- 是否需要扫码。
- 装货扫码字段要求。
- 是否校验物料编码。
- 是否校验批次。
- 是否校验工单。
- 是否校验数量。
- 是否需要 MES 装货前校验。
- 是否允许 MES 异常时重试。
- 是否允许 MES 异常时人工放行。
- 是否需要格口空闲校验。
- 是否允许同格口多物料。
- 是否允许混批。
- 是否需要传感器确认物体存在。
- 是否允许人工确认替代传感器确认。
- 装货完成后是否回传 MES。
- 装货完成回传 MES 时是否包含存货 OP 信息。

如果模板配置装货必须扫码或必须 MES 校验，则校验未通过时站点作业层不得打开格口。

如果模板配置装货完成后需要向 MES 回传存货 OP 信息，则装货阶段应同时要求 OP 身份认证和绑定存货 OP。站点作业层应以实际完成存料操作的 OP 作为存货 OP，不应使用任务创建人、管理员或系统接口用户替代。

### 3.3 运输或送货阶段配置

运输或送货阶段配置用于定义物料随 AGV 从起始站点移动到目标站点过程中需要满足的业务约束和安全要求。

运输或送货阶段至少应支持：

- 是否允许进入运输阶段。
- 离开装货站点前是否必须确认格口关闭或锁状态恢复。
- 运输过程中是否禁止普通业务开格口。
- 运输过程中是否持续检查安全联锁状态。
- 到达目标站点后是否自动进入取货或卸货作业。
- 是否允许到达指定站点后进入驻点发料状态。
- 驻点发料时是否允许多个不同 OP 分别领取不同物料。
- 驻点发料时是否禁止无呼叫返回物料间补料。
- 是否允许 OP 呼叫后返回物料间补料。
- 低电量时是否允许中断驻点并返回充电点。
- 充电完成后是否自动返回原驻点继续发料。
- 运输异常时是否允许人工干预。
- 运输异常是否需要回传 MES。

流程模板只定义运输或送货阶段的业务规则，不应定义 AGV 需要移动到哪个具体站点。具体起始站点、目标站点和 RCS 站点编码应来自任务数据、站点配置或机器人任务层。

当模板配置为驻点发料模式时，复合机器人发货柜到达指定发料站点后，应保持驻点等待 OP 取料。不同 OP 可根据任务、权限和格口绑定关系领取不同物料。除低电量返回充电、异常处理或 OP/授权人员呼叫补料外，系统不应自动返回物料间补料。

### 3.4 取货阶段配置

取货阶段配置用于控制 OP 在取货站点执行取货时需要完成哪些步骤。

取货阶段至少应支持：

- 是否允许取货。
- 是否需要 OP 身份认证。
- 是否需要指定角色 OP。
- 是否绑定领货 OP。
- 是否要求与存货 OP 相同。
- 是否允许非指定 OP 代取。
- 代取是否需要主管或管理员授权。
- 是否需要扫码。
- 取货扫码字段要求。
- 是否需要取货凭证。
- 是否校验物料编码。
- 是否校验批次。
- 是否校验工单。
- 是否校验任务目标站点。
- 是否需要 MES 取货前校验。
- 是否允许 MES 异常时重试。
- 是否允许 MES 异常时人工放行。
- 是否需要传感器确认物体已取出。
- 是否允许人工确认替代传感器确认。
- 取货完成后是否回传 MES。
- 取货完成回传 MES 时是否包含领货 OP 信息。

如果模板配置指定 OP 取货，则非指定 OP 不得打开格口。若模板允许代取，也必须记录授权人、代取人、原因和时间。

如果模板配置取货完成后需要向 MES 回传领货 OP 信息，则取货阶段应同时要求 OP 身份认证和绑定领货 OP。站点作业层应以实际完成取料操作的 OP 作为领货 OP；若存在代取，应回传实际代取 OP，并记录原指定 OP、授权人和代取原因。

### 3.5 扫码配置

扫码配置用于定义装货或取货阶段需要扫描哪些条码，以及每类条码如何校验。

扫码字段可包括：

- 物料码。
- 批次码。
- 工单码。
- 数量码。
- 站点码。
- 取货凭证。
- 包装码。
- 自定义业务码。

每个扫码字段至少应支持：

- 字段名称。
- 是否必扫。
- 是否允许重复扫描。
- 是否需要与任务字段匹配。
- 是否需要与 MES 返回结果匹配。
- 校验失败处理方式。
- 界面提示内容。

扫码失败时，系统应提示失败原因并记录日志。对于必扫字段，未完成扫码不得进入开格口步骤。

### 3.6 OP 认证与权限配置

OP 认证与权限配置用于定义作业过程中是否需要识别现场操作人员及其权限范围。

至少应支持：

- 装货是否需要 OP 认证。
- 取货是否需要 OP 认证。
- 允许操作的角色。
- 是否绑定存货 OP。
- 是否绑定领货 OP。
- 是否允许代操作。
- 代操作授权角色。
- 是否记录非法尝试。
- OP 员工编号输入方式，例如手动输入或扫码输入。
- 是否允许手动输入班组。
- 是否允许手动输入班次。
- 认证超时处理方式。

当模板要求 OP 认证时，站点作业层应在认证通过后才允许继续执行后续步骤。

一期 OP 认证可基于员工编号完成。界面应支持手动输入员工编号，也可支持扫码输入员工编号；班组和班次可由 OP 或授权人员手动输入，并随本次作业记录。

### 3.7 MES 交互配置

MES 交互配置用于定义流程中哪些节点需要与 MES 进行校验或回传。

MES 校验节点和回传节点属于可选能力。流程模板只配置当前流程是否需要启用对应 MES 校验或回传；MES 实际支持哪些校验节点、回传节点、字段和异常返回能力，应在 MES 接口需求或接口设计文档中定义。

至少应支持：

- 是否需要 MES 装货前校验。
- 是否需要 MES 取货前校验。
- 是否需要装货完成回传。
- 是否需要取货完成回传。
- 装货完成回传是否包含存货 OP 编号和名称。
- 取货完成回传是否包含领货 OP 编号和名称。
- 是否需要异常状态回传。
- MES 校验失败处理方式。
- MES 通信异常重试次数。
- MES 通信异常是否允许人工放行。
- MES 回传失败是否阻止任务完成。

MES 交互失败时，系统应根据模板配置进入重试、等待、异常或授权放行流程。

当模板要求完成回传包含 OP 信息时，系统应在回传前确认对应作业阶段已完成 OP 认证和 OP 绑定。若无法取得实际存货 OP 或领货 OP，系统不得生成缺失 OP 的正常完成回传，应按模板配置进入等待、异常或授权处理流程。

### 3.8 传感器确认配置

传感器确认配置用于定义装货或取货完成后是否必须依赖格口物体检测传感器。

至少应支持：

- 装货后是否要求检测到有物体。
- 取货后是否要求检测到无物体。
- 传感器状态未知时处理方式。
- 传感器异常时是否允许人工确认。
- 人工确认所需权限。
- 人工确认是否必须填写原因。
- 传感器确认超时时间。

如果模板配置传感器强确认，则传感器结果不满足要求时不得直接完成作业，除非模板明确允许授权放行。

传感器确认不是所有流程的必选能力，应由流程模板决定是否启用。若目标格口硬件未配置对应传感器，系统不得强制执行传感器确认；若模板要求传感器强确认但目标格口不具备传感器能力，应视为模板与硬件配置不匹配，任务不得按普通流程继续执行。

### 3.9 格口规则配置

格口规则配置用于定义任务与格口之间的业务约束。

至少应支持：

- 是否允许系统自动分配格口。
- 是否允许人工指定格口。
- 是否允许 MES 指定格口。
- 是否要求格口空闲。
- 是否允许同格口多物料。
- 是否允许同格口混批。
- 是否允许跨任务共用格口。
- 格口异常时处理方式。
- 格口开锁失败时重试方式。

格口实际开锁仍由站点作业层完成业务授权后调用格口控制层执行。流程模板不得绕过站点作业层直接打开格口。

### 3.10 异常处理配置

异常处理配置用于定义不同异常发生后的处理策略。

异常类型可包括：

- OP 认证失败。
- 扫码失败。
- MES 校验失败。
- MES 通信异常。
- 格口不可用。
- 开锁失败。
- 关门确认失败。
- 传感器确认失败。
- 作业超时。
- 非指定 OP 操作。
- 站点不匹配。
- 任务状态不允许操作。

处理方式可包括：

- 提示并允许重试。
- 等待人工处理。
- 进入异常状态。
- 禁止继续执行。
- 允许主管授权放行。
- 允许管理员强制关闭。
- 回传 MES 异常状态。

对于影响防错料、防混批、防误开门的关键异常，系统不得默认放行，必须由模板明确配置且满足权限要求后才允许人工处理。

一期人工放行应采用保守策略。系统可支持主管或管理员对非安全类、非强防错类异常进行授权放行，例如 MES 临时通信异常、扫码设备故障但人工核对无误、传感器状态未知但现场确认完成等。对于格口未关闭、安全联锁不通过、站点不匹配、非任务格口开锁、OP 无权限、物料明显不匹配等高风险异常，不应允许普通人工放行。

人工放行必须记录放行人、操作人、放行原因、关联任务、关联格口、原异常类型和放行时间。

### 3.11 界面提示配置

界面提示配置用于定义柜端 HMI 或远程操作端在不同步骤展示给 OP 的提示信息。

至少应支持：

- 当前步骤名称。
- 操作提示。
- 扫码提示。
- 等待提示。
- 异常提示。
- 是否显示物料信息。
- 是否显示批次信息。
- 是否显示目标格口。
- 是否显示下一步动作。
- 是否允许界面展示人工确认按钮。
- 是否允许界面展示授权放行入口。

界面提示配置只影响展示内容，不应改变业务规则。界面不得根据本地判断跳过站点作业层要求的认证、扫码、校验或确认步骤。

## 4. 模板匹配与绑定

### 4.1 模板匹配时机

系统应在任务创建或任务进入执行前确定任务绑定的流程模板。

对于 MES 任务，系统应在接收并转换为内部任务时根据任务来源、任务类型、物料类型和业务字段匹配模板。

对于人工任务，系统应在界面创建任务时根据用户选择或系统规则匹配模板。

### 4.2 模板匹配优先级

当多个模板满足条件时，系统应使用明确的优先级规则。

模板匹配优先级应允许管理员配置，以适应不同客户、产线、区域或站点的业务要求。

系统可预置以下默认优先级，管理员可按现场规则调整：

1. 物料编码精确匹配。
2. 物料类型匹配。
3. 任务类型和任务来源匹配。
4. 客户、产线、区域或站点默认模板匹配。
5. 站点类型匹配。
6. 默认模板。

如果匹配结果不唯一，系统应提示模板配置冲突，不应随机选择模板。

系统应支持按客户、产线、区域或站点维护不同默认模板。当多个默认模板同时命中时，应按管理员配置的优先级选择。

### 4.3 模板绑定要求

任务绑定模板后，应记录模板编号、模板版本和模板快照。

模板绑定后，站点作业层应基于该模板版本执行装货、取货、确认和异常处理流程。

任务执行过程中不得更换流程模板。若发现模板绑定错误，应取消或关闭原任务，并重新创建绑定正确模板的新任务，避免执行过程前后规则不一致。

## 5. 流程执行要求

### 5.1 执行原则

站点作业层执行站点作业时，应读取任务绑定的流程模板，并根据模板决定当前作业需要执行的步骤。

流程模板应影响以下运行行为：

- 当前站点是否允许装货或取货。
- 是否要求 OP 认证。
- 是否要求扫码。
- 扫码需要校验哪些字段。
- 是否调用 MES 校验。
- 是否允许打开格口。
- 是否需要传感器确认。
- 是否允许人工确认。
- 是否允许异常放行。
- 作业完成后是否回传 MES。
- 作业完成回传 MES 时是否携带实际操作 OP 信息。
- 界面应提示 OP 执行哪些操作。

### 5.2 装货执行要求

装货作业时，站点作业层应按模板执行装货阶段规则。

通用执行顺序建议为：

1. 确认任务和站点允许装货。
2. 读取任务绑定的流程模板。
3. 根据模板判断是否需要 OP 认证。
4. 根据模板判断是否需要扫码。
5. 根据模板执行本地业务校验。
6. 根据模板执行 MES 装货前校验。
7. 根据模板和格口状态判断是否允许开格口。
8. 调用格口控制层打开指定格口。
9. 等待 OP 放入物料并关闭格口。
10. 根据模板执行传感器确认或人工确认。
11. 根据模板绑定实际存货 OP。
12. 根据模板判断是否向 MES 回传装货完成结果和存货 OP 信息。
13. 更新任务、格口和作业会话状态。

模板未启用的步骤可以跳过，但跳过原因应能通过模板配置追溯。

如果模板要求装货完成回传 MES 且回传内容包含存货 OP，则站点作业层应在回传前确认实际存货 OP 已完成认证并已绑定到本次装货作业。

### 5.3 取货执行要求

取货作业时，站点作业层应按模板执行取货阶段规则。

通用执行顺序建议为：

1. 确认任务和站点允许取货。
2. 读取任务绑定的流程模板。
3. 根据模板判断是否需要 OP 认证。
4. 根据模板判断是否校验指定 OP 或代取权限。
5. 根据模板判断是否需要扫码或取货凭证。
6. 根据模板执行本地业务校验。
7. 根据模板执行 MES 取货前校验。
8. 根据模板和格口状态判断是否允许开格口。
9. 调用格口控制层打开指定格口。
10. 等待 OP 取出物料并关闭格口。
11. 根据模板执行传感器确认或人工确认。
12. 根据模板绑定实际领货 OP。
13. 根据模板判断是否向 MES 回传取货完成结果和领货 OP 信息。
14. 更新任务、格口和作业会话状态。

若模板要求指定 OP 领取，则站点作业层应在开格口前完成身份和权限校验。

如果模板要求取货完成回传 MES 且回传内容包含领货 OP，则站点作业层应在回传前确认实际领货 OP 已完成认证并已绑定到本次取货作业。

### 5.4 异常执行要求

发生异常时，站点作业层应根据模板配置判断后续处理方式。

系统应区分：

- 可重试异常。
- 需等待人工处理异常。
- 可授权放行异常。
- 必须终止作业异常。
- 需回传 MES 的异常。

异常处理过程中应记录异常类型、发生步骤、模板配置、操作人、授权人、处理结果和时间。

## 6. 模板管理需求

### 6.1 模板新增

系统应支持管理员或具备权限的用户新增流程模板。

新增模板时应至少填写模板基础信息、适用条件、装货配置、取货配置和异常处理配置。

系统应对模板配置进行完整性校验，避免出现无法执行或互相矛盾的规则。

一期不要求单独建设流程模板管理界面，流程模板可先通过后台配置方式维护。后台配置变更仍应记录操作人、操作时间、变更内容和变更原因。

### 6.2 模板修改

系统应支持对未启用或草稿状态的模板进行修改。

对于已启用且已被任务引用的模板，修改时应保留历史版本。新版本发布后只影响后续新任务，不影响已经绑定旧版本的任务。

### 6.3 模板启用和停用

模板启用前应通过配置校验。

模板停用后不得被新任务匹配或绑定，但历史任务仍应能够查询原模板规则和执行记录。

系统应至少保证同一业务范围内存在可用默认模板，避免任务无法创建。

### 6.4 模板复制

系统可支持从已有模板复制生成新模板，便于在相近业务流程上进行调整。

复制模板后，应生成新的模板编号或版本，并要求用户确认适用条件和关键配置。

### 6.5 模板校验

模板保存、启用或发布时应进行配置校验。

至少应校验：

- 模板名称和编号是否唯一。
- 适用条件是否完整。
- 是否与其他启用模板产生冲突。
- 必扫字段是否定义了校验规则。
- MES 校验启用时是否定义处理方式。
- 传感器强确认启用时是否定义异常处理方式。
- 允许人工放行时是否定义授权角色。
- 指定 OP 或代取规则是否互相矛盾。

## 7. 典型流程模板

流程模板应优先按业务运行模式划分为驻点发料、多点配送和多点收料三类。普通辅料、受控物料、人工配送、传感器强校验、MES 强校验等内容，是具体模板中的规则特征，可与上述业务运行模式组合使用。例如系统可以配置“驻点发料-受控物料流程”、“多点配送-MES 强校验流程”或“多点收料-普通辅料流程”。

### 7.1 普通辅料流程

普通辅料流程适用于风险较低、对 OP 绑定要求不强的普通配送任务。

建议配置：

- 装货需要扫描物料码。
- 装货可不强制 OP 认证，或只记录当前登录 OP。
- 取货可不强制扫码。
- 取货需要 OP 人工确认。
- 不强制绑定存货 OP 和领货 OP。
- 不允许打开非任务格口。
- 作业完成后记录任务、格口、物料和操作时间。

### 7.2 受控物料流程

受控物料流程适用于对物料、批次、工单和领取人要求严格的任务。

建议配置：

- 装货和取货均需要 OP 认证。
- 装货需要扫描物料码、批次码和工单码。
- 取货需要扫描取货凭证或物料码。
- 装货绑定存货 OP。
- 取货绑定领货 OP。
- 不允许非指定 OP 取货，或代取必须主管授权。
- 需要 MES 装货前或取货前校验。
- 传感器异常时进入异常或授权处理。

### 7.3 人工配送流程

人工配送流程适用于授权人员通过界面手动创建的任务。

建议配置：

- 任务来源为人工创建。
- 创建任务时选择物料、数量、起始站点、目标站点和目标格口规则。
- 装货和取货均记录 OP。
- 可按物料风险决定是否扫码。
- 不依赖 MES 下发任务，但可按配置回传或记录本地日志。
- 异常关闭必须由授权用户操作。

### 7.4 传感器强校验流程

传感器强校验流程适用于要求系统必须确认格口内物体状态的任务。

建议配置：

- 装货后必须检测到格口有物体。
- 取货后必须检测到格口无物体。
- 传感器状态未知不得自动完成作业。
- 传感器异常时进入异常或等待授权。
- 人工确认替代传感器确认必须记录授权原因。

### 7.5 MES 强校验流程

MES 强校验流程适用于必须由 MES 确认作业合法性的任务。

建议配置：

- 装货前调用 MES 校验物料是否允许装入。
- 取货前调用 MES 校验 OP 是否允许领取。
- 装货或取货完成后回传 MES。
- MES 校验失败不得开格口。
- MES 通信异常按模板配置重试。
- 重试失败后进入异常或授权处理。

### 7.6 驻点发料流程

驻点发料流程适用于复合机器人发货柜到达指定站点后长期停留，由多个 OP 按任务或权限分别领取不同物料的业务模式。

建议配置：

- 业务运行模式为驻点发料。
- 复合机器人到达指定发料站点后进入驻点等待状态。
- 支持多个不同 OP 在同一驻点分别领取不同物料。
- 取货时按模板执行 OP 认证、权限校验、扫码、格口授权和领货 OP 绑定。
- 取货完成后可按模板向 MES 回传实际领货 OP、物料、格口和时间。
- 低电量时允许返回充电点。
- 充电完成后应自动返回原驻点继续发料。
- 除 OP 呼叫补料、授权人员呼叫补料、低电量充电或异常处理外，不应自动返回物料间补料。
- OP 呼叫补料时，应记录呼叫人、呼叫时间、补料原因和补料任务。

### 7.7 多点配送流程

多点配送流程适用于在一个装货点上料后，复合机器人发货柜依次前往一个或多个指定机台、产线或站点完成卸货或发料的传统配送模式。

建议配置：

- 业务运行模式为多点配送。
- 装货阶段在统一上料点完成。
- 装货时可按物料风险执行 OP 认证、扫码、MES 校验和存货 OP 绑定。
- 运输阶段按任务目标站点顺序移动。
- 到达每个目标站点后，站点作业层按模板执行取货或卸货流程。
- 每个目标站点只能打开与当前任务、当前站点、当前 OP 权限匹配的格口。
- 每个站点的取货或卸货完成结果应独立记录，并可按模板回传 MES。
- 所有目标站点完成后，任务进入完成、等待、返回或下一任务状态。

### 7.8 多点收料流程

多点收料流程适用于复合机器人发货柜从多个机台、产线或站点收取物料，再送到一个指定地点统一下料的传统回收模式。

建议配置：

- 业务运行模式为多点收料。
- 复合机器人按任务要求依次到达多个收料站点。
- 每个收料站点可按模板执行 OP 认证、扫码、MES 校验、格口授权和存货 OP 绑定。
- 每个站点收料完成后，应确认格口关闭或锁状态恢复后才允许离站。
- 运输过程中禁止普通业务开格口。
- 到达统一下料点后，按模板执行取货或卸货流程。
- 下料完成后可按模板向 MES 回传实际下料 OP、物料、格口、来源站点和时间。
- 任一收料站点异常时，应根据模板配置决定重试、跳过、等待人工处理或终止任务。

## 8. 与其他层的关系

### 8.1 与任务管理层的关系

任务管理层在创建任务或接收外部任务时，应根据任务信息匹配并绑定流程模板。

任务管理层负责维护任务生命周期状态，流程模板层不负责决定 AGV 是否派车、任务是否完成或任务整体状态机如何流转。

### 8.2 与站点作业层的关系

站点作业层是流程模板的主要执行方。

站点作业层应根据任务绑定的模板版本，决定当前站点作业是否需要 OP 认证、扫码、MES 校验、格口授权、传感器确认、人工确认或异常放行。

站点作业层不得绕过流程模板中配置的强制校验项。

### 8.3 与格口控制层的关系

流程模板层不直接调用格口控制层。

流程模板可定义开格口前需要满足的业务规则，例如是否要求扫码、是否要求 MES 校验、是否要求目标格口空闲等。站点作业层完成业务授权后，再调用格口控制层执行实际开锁。

### 8.4 与界面层的关系

界面层应根据站点作业层返回的当前步骤、允许操作项和模板提示内容进行展示。

界面层不应自行决定业务流程，不应自行跳过认证、扫码、MES 校验或确认步骤。

模板中的界面提示内容只用于展示和引导，不应作为业务判断依据。

### 8.5 与 MES 的关系

流程模板可定义是否需要 MES 校验或回传，以及 MES 异常时的处理策略。

实际 MES 接口调用应由对应业务服务或站点作业层发起，流程模板层只提供规则依据。

当模板要求存料或取料完成后向 MES 回传 OP 信息时，MES 回传字段应取自站点作业层记录的实际存货 OP 或实际领货 OP。系统不应使用任务创建人、管理员账号、接口用户或当前登录但未实际完成作业的人员替代实际操作 OP。

## 9. 日志与追溯需求

系统应记录流程模板相关日志，便于追溯任务为何采用某个流程，以及每一步为何被允许或拒绝。

至少应记录：

- 模板新增、修改、启用、停用日志。
- 模板版本发布日志。
- 任务绑定模板日志。
- 模板匹配结果。
- 模板匹配失败原因。
- 任务执行时使用的模板版本。
- 被跳过或启用的流程步骤。
- 因模板规则导致的拒绝操作。
- 人工放行或授权操作记录。

模板追溯信息应支持按任务编号、模板编号、模板版本、操作人和时间范围查询。

## 10. 异常与约束

### 10.1 未匹配到模板

当任务无法匹配到可用流程模板时，系统不得直接创建可执行任务。

系统应提示模板缺失原因，并允许管理员维护模板后重新处理。

### 10.2 模板冲突

当多个启用模板同时匹配同一任务且优先级无法区分时，系统应判定为模板冲突。

模板冲突时，系统不得随机选择模板，应提示管理员处理配置冲突。

### 10.3 模板被停用

模板停用后不得用于新任务。

已绑定停用前版本的任务仍应按原模板版本继续执行。任务执行过程中不得更换流程模板。

### 10.4 模板配置不完整

模板配置不完整时不得启用。

例如启用了扫码但未定义扫码字段，启用了人工放行但未定义授权角色，启用了 MES 校验但未定义失败处理方式，均应视为配置不完整。

### 10.5 模板规则与安全联锁冲突

流程模板不得绕过安全联锁规则。

即使模板允许人工确认或授权放行，只要格口控制层或机器人任务层判断存在阻止移动或阻止开格口的安全风险，系统仍不得执行普通业务开格口或允许 AGV 离站。

## 11. 非功能需求

### 11.1 可维护性

流程模板配置应便于现场维护人员理解和调整。

系统应避免使用过于复杂、难以验证的自由脚本或任意流程编排方式。一期应以明确配置项和固定执行框架为主。

### 11.2 一致性

同一任务在柜端 HMI、远程操作端或管理端看到的流程步骤和可执行动作应保持一致。

不同界面不得各自维护不同的业务流程规则。

### 11.3 可追溯性

任何影响任务执行的模板规则都应能追溯到具体模板版本。

历史任务查询时，应能查看当时使用的模板规则，而不是只显示当前最新模板。

### 11.4 可扩展性

流程模板应允许后续扩展新的配置项，例如更多扫码字段、更多 MES 节点、更多异常处理方式或新的物料风险等级。

新增配置项时，应尽量兼容历史模板版本和历史任务追溯。

## 12. 待确认问题

以下内容需要在详细设计或现场调研阶段进一步确认：

- MES 校验节点、回传节点、字段和异常返回能力应在 MES 接口需求或接口设计文档中进一步定义。
- 人工放行是否需要双人确认，以及不同异常类型对应的审批角色。
- 员工编号、班组和班次是否需要与外部人员系统或 MES 进行校验。
- 按客户、产线、区域或站点维护默认模板时，各维度之间的最终优先级。
