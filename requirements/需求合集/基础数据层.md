# 基础数据层 Master Data Layer

## 1. 文档说明

### 1.1 文档目的

基础数据层负责维护复合机器人发货柜系统运行所需的基础配置数据，包括站点、物料、物料类型、发货柜、格口、OP、角色、权限、流程模板适用条件以及接口映射等。

基础数据层应为任务管理、流程模板、站点作业、MES 接口、RCS 协同、格口控制、界面展示和日志追溯提供统一、稳定、可追溯的配置依据。

本文档用于说明基础数据层在需求阶段需要具备的数据对象、配置关系、启停规则、版本管理、权限控制和变更追溯要求，不描述具体数据库表结构、页面布局或代码实现。

### 1.2 职责边界

基础数据层负责“系统运行依赖的基础配置是什么、配置之间如何关联、配置如何生效和追溯”。

简单来说：

- 任务管理层读取基础数据来创建和校验任务。
- 流程模板层读取基础数据来匹配模板适用条件。
- 站点作业层读取 OP、站点、物料和权限配置来判断是否允许作业。
- RCS 协同层读取站点与 RCS 编码映射来下发移动任务。
- 格口控制层读取发货柜、格口和硬件映射来控制格口。
- 基础数据层负责维护这些配置本身。

基础数据层不直接执行任务、不直接调用 MES 或 RCS、不直接开格口。

### 1.3 一期建设原则

一期基础数据应优先支持配置清晰、启停可控、修改可追溯。

一期至少应支持：

- 站点配置。
- 物料与物料类型配置。
- 发货柜配置。
- 格口配置。
- OP 与角色配置。
- 权限配置。
- 流程模板适用条件配置。
- MES 与 RCS 编码映射配置。
- 基础数据启用、禁用和变更记录。

## 2. 基础数据对象

### 2.1 站点 Station

站点是复合机器人可以到达并执行等待、装货、取货、驻点、充电或异常处理的位置。

站点至少包含：

- 站点编号。
- 站点名称。
- 站点类型。
- RCS 站点编码。
- MES 站点编码，如果有。
- 是否允许装货。
- 是否允许取货。
- 是否允许等待。
- 是否允许驻点。
- 是否允许充电。
- 启用/禁用状态。

站点编号一旦被任务、日志或模板引用，不应随意修改。若现场站点编码变更，应通过配置变更记录保留历史映射。

### 2.2 物料 Material

物料是系统执行装货、配送、发放、收料和退料的对象。

物料至少包含：

- 物料编码。
- 物料名称。
- 物料类型。
- 规格型号。
- 单位。
- 是否启用。
- 是否需要扫码。
- 是否需要 MES 校验。
- 是否受控。
- 默认流程模板适用条件，如果有。

物料信息可从 MES 同步，也可由系统维护。若系统与 MES 同时维护，应明确主数据来源和冲突处理规则。

### 2.3 物料类型 Material Type

物料类型用于对物料进行业务规则分类。

物料类型可包括：

- 普通辅料。
- 受控物料。
- 贵重物料。
- 需扫码物料。
- 需 MES 强校验物料。
- 可人工放行物料。

物料类型至少包含：

- 类型编号。
- 类型名称。
- 是否需要 OP 认证。
- 是否需要扫码。
- 是否需要 MES 校验。
- 是否需要传感器确认。
- 是否允许代取。
- 是否允许人工放行。
- 启用/禁用状态。

物料类型是流程模板匹配的重要条件之一。

### 2.4 发货柜 Cabinet

发货柜是安装在复合机器人上的多格口存取设备。

发货柜至少包含：

- 发货柜编号。
- 发货柜名称。
- 关联机器人编号。
- 柜体型号。
- 格口数量。
- 前后侧配置。
- 是否启用。
- 当前通信状态。
- 当前业务状态。

当前阶段，一个复合机器人默认绑定一个发货柜。若现场需要换柜，应补充柜体绑定、解绑和换柜追溯要求。

### 2.5 格口 Slot

格口是发货柜中的独立存取单元。

格口至少包含：

- 格口编号。
- 所属发货柜编号。
- 格口序号。
- 内部编码。
- 显示名称。
- 所在侧别。
- 行号。
- 列号。
- 是否启用。
- 是否允许自动分配。
- 默认物料限制，如果有。
- 硬件 IO 映射编号。

格口编号应保持稳定。历史任务、库存、日志和追溯数据都应使用稳定的格口编号。

### 2.6 OP 操作员

OP 是执行装货、取货、扫码、确认和异常处理的现场人员。

OP 至少包含：

- OP 编号。
- OP 名称。
- 登录账号或工号。
- 班组。
- 部门。
- 角色。
- 权限范围。
- 是否启用。
- 认证方式。

OP 信息需要用于 MES 回传、站点作业校验和日志追溯。

### 2.7 角色 Role

角色用于定义一类人员可执行的操作范围。

角色可包括：

- OP 操作员。
- 主管或班组长。
- 管理员。
- 维护人员。
- 系统接口用户。

角色至少包含：

- 角色编号。
- 角色名称。
- 角色描述。
- 关联权限。
- 启用/禁用状态。

### 2.8 权限 Permission

权限用于控制用户是否可执行某类业务操作或配置操作。

权限可包括：

- 查看任务。
- 执行装货。
- 执行取货。
- 扫码确认。
- 人工创建任务。
- 主管放行。
- 异常关闭任务。
- 修改基础数据。
- 修改流程模板。
- 查看日志追溯。
- 维护硬件配置。

高风险权限应支持二次确认和日志记录。

### 2.9 流程模板适用条件

流程模板适用条件用于判断任务创建时应绑定哪个流程模板。

适用条件可包括：

- 任务类型。
- 业务运行模式。
- 任务来源。
- 物料类型。
- 物料编码。
- 起始站点类型。
- 目标站点类型。
- 是否需要 MES 强校验。
- 是否需要 OP 绑定。
- 是否需要传感器确认。
- 是否允许人工放行。

多个模板同时满足条件时，应有明确优先级规则，避免任务创建时模板匹配不确定。

### 2.10 接口编码映射

接口编码映射用于维护系统内部编码与外部系统编码之间的关系。

编码映射可包括：

- 系统站点编号与 RCS 站点编码。
- 系统站点编号与 MES 站点编码。
- 系统物料编码与 MES 物料编码。
- 系统 OP 编号与 MES OP 编号。
- 系统机器人编号与 RCS 设备编码。

编码映射错误会直接影响任务执行和接口回传，应纳入高风险配置管理。

## 3. 配置关系

### 3.1 站点与业务能力关系

站点应明确允许的业务能力。

例如：

- 装货站点允许装货，不一定允许取货。
- 取货站点允许取货，不一定允许装货。
- 驻点可允许驻点发料，也可仅用于等待。
- 充电站只用于回充，不应作为普通作业站点。

任务和流程模板执行时，应校验当前站点是否具备对应业务能力。

### 3.2 物料与流程模板关系

物料和物料类型会影响流程模板匹配。

例如：

- 普通辅料可采用普通扫码流程。
- 受控物料可要求 OP 绑定和 MES 强校验。
- 贵重物料可要求主管放行或二次确认。

系统不应通过硬编码物料编号来决定业务流程，应通过物料类型和模板适用条件配置实现。

### 3.3 发货柜与格口关系

一个发货柜包含多个格口。

格口配置应从属于发货柜。发货柜禁用时，其下所有格口不得参与普通业务；单个格口禁用时，不影响其他格口。

### 3.4 OP、角色与权限关系

一个 OP 可绑定一个或多个角色。

角色关联权限，权限决定用户可执行的操作。关键业务操作应同时校验角色权限和流程模板要求。

## 4. 启用与禁用规则

### 4.1 基础数据启用

基础数据启用前应完成必要字段校验。

例如：

- 站点启用前必须配置 RCS 站点编码。
- 格口启用前必须配置所属发货柜和必要硬件映射。
- OP 启用前必须配置角色。
- 流程模板适用条件启用前不得存在明显冲突。

### 4.2 基础数据禁用

基础数据禁用后，不应再参与新任务创建、自动分配或普通业务操作。

已经被历史任务引用的数据应保留，不得物理删除导致历史追溯缺失。

### 4.3 删除限制

已被任务、日志、模板、库存或接口记录引用的基础数据，不建议物理删除。

系统应优先使用禁用、停用或失效时间来处理不再使用的数据。

## 5. 变更管理

### 5.1 变更审批

高风险配置变更应要求具备相应权限的人员操作。

高风险配置包括：

- RCS 站点编码。
- MES 编码映射。
- 格口 IO 映射。
- 物料类型规则。
- 角色权限。
- 流程模板适用条件。

### 5.2 变更生效

基础数据变更应明确生效范围。

建议原则：

- 新任务使用最新启用配置。
- 已创建任务继续使用创建时绑定的关键配置快照。
- 历史任务追溯应展示当时使用的配置值。

### 5.3 变更追溯

基础数据变更应记录：

- 配置对象。
- 变更前内容。
- 变更后内容。
- 变更人。
- 变更时间。
- 变更原因。
- 生效时间。

## 6. 日志与追溯

基础数据层应记录：

- 站点配置新增、修改、启用、禁用记录。
- 物料和物料类型配置变更记录。
- 发货柜和格口配置变更记录。
- OP、角色和权限变更记录。
- 流程模板适用条件变更记录。
- MES 与 RCS 编码映射变更记录。

基础数据变更日志应能支持按时间、对象、操作人和配置类型查询。
