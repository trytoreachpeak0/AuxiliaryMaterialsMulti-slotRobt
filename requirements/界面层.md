# 界面层 User Interface Layer

## 1. 文档说明

### 1.1 文档目的

界面层负责向 OP、主管、管理员和维护人员展示任务、站点、复合机器人、发货柜、格口、流程步骤和异常状态，并采集用户的身份认证、扫码、确认、授权、人工任务创建、补料呼叫和异常处理操作。

界面层应向上体现业务操作入口，向下调用任务管理层、站点作业层、流程模板层、格口状态查询和日志查询等能力。

本文档用于说明界面层在需求阶段需要具备的界面类型、角色权限、展示内容、操作入口、状态提示、异常提示和追溯要求，不描述具体 UI 样式、前端框架、页面布局细节或接口报文格式。

### 1.2 职责边界

界面层负责“展示、提示和采集输入”。

简单来说：

- 任务管理层负责“任务状态和任务生命周期”。
- 流程模板层负责“不同业务流程规则”。
- 站点作业层负责“到站后的 OP 作业流程和开格口前授权判断”。
- 格口控制层负责“格口状态查询和被授权后的开锁执行”。
- 界面层负责“把当前任务、当前步骤和允许操作展示给用户，并把用户输入提交给对应业务层”。

界面层不得自行决定业务流程，不得自行跳过 OP 认证、扫码、MES 校验、格口授权、安全联锁或确认步骤。

### 1.3 一期建设原则

一期界面应优先保证现场可操作性、状态清晰、异常可见和操作可追溯。

界面应根据任务管理层、站点作业层和流程模板返回的状态动态展示当前步骤和允许操作项。不同界面入口看到的任务状态、格口状态和异常状态应保持一致。

## 2. 界面类型

### 2.1 柜端 HMI

柜端 HMI 运行在发货柜上方电脑或触控屏上，主要面向现场 OP。

柜端 HMI 用于：

- OP 身份认证。
- 扫码输入。
- 查看当前站点。
- 查看当前任务或可领取物料。
- 查看需要操作的格口。
- 按流程模板引导装货、取货、收料或下料。
- 发起操作确认。
- 查看异常原因和处理提示。
- 驻点发料模式下领取物料。
- 驻点发料模式下呼叫补料。

柜端 HMI 不应作为主要系统配置入口。流程模板、接口参数、权限、站点、格口配置等高风险配置应在管理配置端完成。

### 2.2 远程操作端

远程操作端供 OP、主管、管理员或授权人员通过本地客户端或浏览器查看系统状态并执行授权范围内的业务操作。

远程操作端用于：

- 查看任务看板。
- 查看复合机器人和发货柜状态。
- 查看格口状态。
- 创建人工任务。
- 查看驻点发料状态。
- 发起取货请求。
- 发起补料呼叫。
- 查看异常告警。
- 主管或管理员授权放行。
- 查看日志和追溯信息。

远程操作端可以复用部分柜端 HMI 的作业能力，但高风险操作应受权限和二次确认约束。

### 2.3 管理配置端

管理配置端供管理员或维护人员维护系统基础配置。

管理配置端用于：

- 用户和角色管理。
- OP 权限配置。
- 站点配置。
- 发货柜配置。
- 格口配置。
- 物料类型配置。
- 流程模板配置。
- MES 接口参数配置。
- RCS 接口参数配置。
- 异常处理和任务关闭。
- 日志和追溯查询。

管理配置端的高风险操作必须记录操作人、操作时间、操作原因和变更内容。

## 3. 角色与权限

### 3.1 OP 操作员

OP 可通过界面执行：

- 登录或身份认证。
- 查看与本人或当前站点相关的任务提示。
- 扫码。
- 装货、取货、收料、下料确认。
- 查看当前可操作格口。
- 驻点发料模式下领取物料。
- 按权限发起补料呼叫。
- 查看本次操作异常提示。

OP 不应具备越权开锁、修改流程模板、关闭异常任务、修改接口参数或强制解除安全联锁的权限。

### 3.2 主管或班组长

主管或班组长可通过界面执行：

- 查看任务看板。
- 查看异常告警。
- 创建人工任务。
- 授权 OP 重新操作。
- 授权代取。
- 对允许放行的异常进行确认。
- 查看本班组相关日志。
- 发起补料呼叫。

主管或班组长的授权操作必须记录授权人、被授权人、原因、时间和关联任务。

### 3.3 管理员

管理员可通过界面执行：

- 用户、角色和权限维护。
- 基础数据维护。
- 流程模板维护。
- 接口参数维护。
- 异常任务关闭。
- 强制开锁。
- 查看全部任务和日志。
- 系统配置和维护操作。

管理员高风险操作必须二次确认，并记录完整审计日志。

### 3.4 系统维护人员

系统维护人员可按权限查看设备通信状态、接口状态、发货柜状态和故障信息。

系统维护人员的维护操作不应绕过业务追溯要求。

## 4. 任务看板需求

### 4.1 任务列表

界面应提供任务看板。

任务看板至少显示：

- 任务编号。
- 任务来源。
- 任务类型。
- 业务运行模式。
- 当前任务状态。
- 当前站点。
- 目标站点或目标站点列表。
- 关联发货柜。
- 关联格口。
- 物料信息。
- 异常信息。
- 创建时间。
- 更新时间。

任务看板应支持按任务状态、业务运行模式、站点、任务来源、异常状态和时间范围筛选。

### 4.2 任务详情

任务详情应显示：

- 任务基础信息。
- 任务明细。
- 站点执行计划。
- 当前流程模板和版本。
- 当前作业步骤。
- 关联格口状态。
- OP 操作记录。
- MES 交互记录。
- RCS 目标站点下发记录。
- 异常处理记录。

任务详情应能支持追溯任务为什么进入当前状态，以及下一步允许执行什么操作。

## 5. 复合机器人与发货柜状态界面

### 5.1 复合机器人状态

界面应显示：

- 复合机器人编号。
- AGV 当前状态。
- 当前站点。
- 目标站点。
- 电量状态。
- 是否处于充电中。
- 是否处于驻点等待。
- RCS 通信状态。
- 当前任务编号。

驻点发料模式下，应明确显示当前驻点、是否可领取、是否正在补料、是否因低电量离开驻点以及充电完成后是否返回驻点。

### 5.2 发货柜状态

界面应显示：

- 发货柜编号。
- 所属复合机器人。
- 发货柜通信状态。
- 发货柜启用/禁用状态。
- 当前格口数量。
- 是否存在阻止移动的格口状态。
- 是否存在异常锁定格口。

### 5.3 格口状态

界面应显示格口布局和状态。

至少显示：

- 格口编号。
- 显示名称。
- 物理位置。
- 启用/禁用状态。
- 业务状态。
- 锁状态。
- 门状态，如果硬件支持。
- 传感器状态，如果配置。
- 关联任务或物料。
- 是否可操作。
- 异常原因。

界面不得仅根据前端本地状态决定格口可操作性，应以站点作业层和格口控制层返回的结果为准。

## 6. OP 作业界面

### 6.1 动态步骤展示

OP 作业界面应根据流程模板和站点作业层返回的当前状态动态展示操作步骤。

界面应支持展示：

- 当前任务。
- 当前站点。
- 当前作业类型。
- 当前步骤。
- 下一步操作提示。
- 当前可操作格口。
- 必扫字段。
- 当前 OP 认证状态。
- 异常提示。

界面不应自行决定跳过某个步骤。是否需要认证、扫码、MES 校验、人工确认或授权放行，应由站点作业层根据任务绑定的流程模板判断。

### 6.2 身份认证

界面应支持 OP 身份认证。

认证方式可包括：

- 账号密码。
- 工牌扫码。
- 刷卡。
- 第三方认证设备。

具体认证方式可在详细设计阶段确认。界面应展示认证成功、认证失败、权限不足和认证超时等状态。

### 6.3 扫码输入

界面应支持扫码输入。

扫码内容可包括：

- 物料码。
- 批次码。
- 工单码。
- 数量码。
- 取货凭证。
- 站点码。
- 包装码。

界面应根据流程模板提示当前需要扫描的字段，并显示校验成功或失败原因。

### 6.4 操作确认

界面应支持 OP 对装货、取货、收料、下料和关门完成进行确认。

确认前，界面应展示必要信息，例如任务、物料、格口、当前 OP 和注意事项。

若流程模板要求传感器确认，界面应展示传感器确认结果。若允许人工确认替代传感器确认，界面应根据权限展示人工确认入口。

## 7. 驻点发料界面

### 7.1 驻点状态展示

驻点发料界面应显示：

- 当前驻点站点。
- 当前可领取物料。
- 当前可领取格口。
- 已领取记录。
- 待领取记录。
- 当前发货柜是否可取料。
- 是否正在补料。
- 是否因低电量离开驻点。
- 预计返回驻点状态，如果可获取。

### 7.2 多 OP 取料

驻点发料模式下，界面应支持多个不同 OP 分别领取不同物料。

每个 OP 取料时应按流程模板执行身份认证、扫码或取货凭证校验、格口授权、取货确认和领货 OP 绑定。

界面应防止多个 OP 同时操作同一格口。

### 7.3 补料呼叫

界面应支持 OP 或授权人员发起补料呼叫。

补料呼叫至少应记录：

- 呼叫人。
- 呼叫时间。
- 当前驻点。
- 补料原因。
- 需要补料的物料或格口，如果有。

驻点发料模式下，除低电量、异常处理或补料呼叫外，界面不应提供普通 OP 直接让机器人返回物料间的入口。

## 8. 多点配送与多点收料界面

### 8.1 多点配送界面

多点配送界面应展示：

- 上料点。
- 目标站点列表。
- 当前执行站点。
- 各目标站点完成状态。
- 每个站点关联任务明细。
- 每个站点允许操作的格口。
- 每个站点实际领货 OP。

到达目标站点后，界面应只显示当前站点允许操作的任务和格口。

### 8.2 多点收料界面

多点收料界面应展示：

- 收料站点列表。
- 当前收料站点。
- 已完成收料站点。
- 待收料站点。
- 每个站点收料明细。
- 每个站点实际存货 OP。
- 统一下料点。

到达统一下料点后，界面应引导 OP 或仓库人员完成下料确认。

## 9. 异常与告警界面

### 9.1 异常展示

界面应清晰展示异常信息。

至少包括：

- 异常类型。
- 异常发生时间。
- 关联任务。
- 关联站点。
- 关联格口。
- 当前处理状态。
- 建议处理方式。

### 9.2 异常处理入口

界面应根据用户权限展示异常处理入口。

可支持：

- 重试。
- 重新扫码。
- 重新认证。
- 主管授权。
- 管理员关闭任务。
- 人工确认。
- 强制开锁。
- 呼叫维护。

高风险异常处理必须要求原因填写和二次确认。

### 9.3 安全联锁提示

当存在未关闭格口、疑似未关闭格口、格口操作中、发货柜通信异常或其他阻止移动条件时，界面应明确提示 AGV 不允许移动。

界面不得提供绕过安全联锁的普通操作入口。

## 10. 管理配置界面

### 10.1 基础数据配置

管理配置端应支持维护：

- 用户和角色。
- OP 权限。
- 站点。
- 复合机器人。
- 发货柜。
- 格口。
- 物料类型。
- 业务运行模式。

### 10.2 流程模板配置

管理配置端应支持维护流程模板。

至少包括：

- 模板基础信息。
- 业务运行模式。
- 适用条件。
- 装货阶段配置。
- 运输或送货阶段配置。
- 取货或卸货阶段配置。
- OP 认证和绑定配置。
- MES 交互配置。
- 异常处理配置。
- 界面提示配置。

流程模板发布前应进行配置校验。

### 10.3 接口配置

管理配置端可支持维护 MES、RCS 和发货柜控制器相关接口参数。

接口配置修改应要求管理员权限，并记录变更日志。

## 11. 日志与追溯界面

界面应支持查询和展示：

- 任务日志。
- OP 操作日志。
- 扫码日志。
- 身份认证日志。
- 开锁日志。
- 格口状态变化日志。
- MES 交互日志。
- RCS 调用日志。
- 异常处理日志。
- 管理配置变更日志。

查询条件至少应支持：

- 任务编号。
- MES 任务编号。
- OP。
- 物料。
- 批次。
- 格口。
- 站点。
- 时间范围。
- 异常类型。

## 12. 界面安全与约束

### 12.1 权限控制

界面所有操作入口都应受权限控制。

前端隐藏按钮不能作为唯一权限控制手段，后端业务层仍必须校验用户权限和业务规则。

### 12.2 防误操作

高风险操作应进行二次确认。

高风险操作包括：

- 强制开锁。
- 人工放行。
- 关闭异常任务。
- 修改流程模板。
- 修改接口参数。
- 取消执行中任务。

### 12.3 状态一致性

界面应及时刷新任务、站点、格口和异常状态。

当界面状态与后端状态不一致时，应以后端最新状态为准，并提示用户刷新或重新操作。

## 13. 非功能需求

### 13.1 易用性

柜端 HMI 应适合现场触控操作，提示清晰，减少 OP 误操作。

关键操作应使用明确文本提示，不应只依赖颜色或图标表达。

### 13.2 可追溯性

通过界面发起的所有业务操作都应记录操作人、时间、入口、任务和结果。

### 13.3 可维护性

界面展示逻辑应尽量基于后端返回的状态、步骤和允许操作项，避免在前端硬编码业务流程。

### 13.4 可扩展性

界面应允许后续扩展新的业务运行模式、流程模板配置项、站点类型和异常处理方式。

## 14. 待确认问题

以下内容需要在详细设计或现场调研阶段进一步确认：

- 柜端 HMI 使用触控屏、工控机还是普通浏览器。
- OP 身份认证具体方式。
- 扫码设备接入方式。
- 远程操作端允许 OP 执行哪些实际作业动作。
- 驻点发料界面是否需要显示库存余量或只显示可领取任务。
- 补料呼叫由普通 OP 发起还是必须主管发起。
- 异常放行是否需要双人确认。
- 管理配置端是否一期全部建设，还是部分配置通过后台维护。
