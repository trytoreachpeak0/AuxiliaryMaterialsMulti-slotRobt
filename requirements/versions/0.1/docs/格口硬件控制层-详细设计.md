## 2. 配置加载

### 2.1 文件组合

| 文件 | 必填 | 说明 |
|------|------|------|
| `slots.generated.yaml` | 是 | 格口清单，勿手改（由脚本生成） |
| `slot-io-mapping.generated.yaml` | 是 | DO/DI 映射 |
| `io-modules.yaml` | 是 | 从 template 复制；**现场提供**各模块 `host`（IP），xlsx 不含 IP，见 [概要 §3.3](格口硬件控制层-概要设计.md) |

启动时合并三份配置；校验规则见 [../wire-cabinet/slot-config/VALIDATION.md](../wire-cabinet/slot-config/VALIDATION.md)。

### 2.2 映射表字段（slot-io-mapping）

**SlotCode**（YAML 字段 `slot_code`）：格口业务编号，全系统对外主键。定义与示例见 [概要设计 §3.1](格口硬件控制层-概要设计.md)。接口 `UnlockAsync(string slotCode)` 只接受该字符串，内部再解析为 `door_position` 与 Modbus 点位。

| 字段 | 类型 | 说明 |
|------|------|------|
| `slot_code` | string | **SlotCode**，如 `F-A01` |
| `door_position` | string | `front(1,1)` |
| `slot_index` | int | 1..54，批量开锁排序与界面布局（**非** 位串下标） |
| `module_key` | string | `C4` / `24` / `67` / `BE` |
| `do_index` | int | 1～16，对应 `DO1`～`DO16`；Modbus 线圈 `do_start + (do_index-1)`（默认 `do_start=100`） |
| `di_index` | int | 1～16，对应 `DI1`～`DI16`；离散输入 `di_start + (di_index-1)`（默认 `di_start=10200`） |
| `wired` | bool | false 时禁止开锁 |
| `enabled_default` | bool | 导入 app_slot 默认是否启用 |

### 2.3 模块连接（io-modules.yaml）

```yaml
unlock:
  output_mode: hardware_pulse   # 本柜默认：只写 DO=1，脉冲由模块产生
  pulse_ms: 300                 # 仅 software_pulse 时有效
  unlock_feedback_timeout_ms: 5000
di_semantics:
  di_active_means_locked: true   # DI=1 锁闭合，DI=0 锁释放（现场已确认）
modules:
  - key: "67"
    host: "192.168.x.x"
    port: 502
    unit_id: 1
    enabled: true
```

## 3. 接口定义（C#）

命名空间建议：`AuxiLink.Cabinet.Hardware`（或业务项目等价命名）。

### 3.1 锁状态

```csharp
public enum HardwareLockState
{
    Locked,
    Unlocked,
    NotConfigured,
    ReadFailed,
    Unknown
}

public enum HardwareUnlockResultCode
{
    Success,
    ModuleOffline,
    NotWired,
    SlotDisabled,
    ConcurrentUnlock,
    WriteFailed,
    FeedbackTimeout,
    FeedbackMismatch,
    CommError
}

public sealed class HardwareUnlockResult
{
    public string SlotCode { get; init; } = "";
    public HardwareUnlockResultCode Code { get; init; }
    public string Message { get; init; } = "";  // 中文，可直接展示
    public TimeSpan Elapsed { get; init; }
}
```

### 3.2 ISlotHardwareService

```csharp
public interface ISlotHardwareService
{

    /// <summary>仅返回参与联锁的格口（enabled ∧ wired）的 DI 状态。</summary>
    Task<IReadOnlyDictionary<string, HardwareLockState>> ReadInterlockLockStatesAsync(CancellationToken ct = default);
    IReadOnlyList<ModuleHealthDto> GetModuleHealth();
    bool IsUnlockInProgress(string slotCode);
}
```

## 4. Modbus 寻址

### 4.1 本柜 IO 模块约定（现场已确认）

本柜 4 块 IO 模块型号一致，**每模块 16 路 DO + 16 路 DI**，Modbus 地址为 **0-based**（库/API 传参即用下列起始地址，不再减 1）：

| 类型 | 起始地址 | 点数 | Excel 点名 |
|------|----------|------|------------|
| DO（线圈 / Write Coils） | **100** | **16** | `DO1`～`DO16` |
| DI（离散输入 / Read Discrete Inputs） | **10200** | **16** | `DI1`～`DI16` |

点名 → Modbus 地址（`do_index` / `di_index` 为导出 YAML 中的 1～16）：

```text
coil_address      = do_start  + (do_index - 1)   # 例 DO12 → 100 + 11 = 111
discrete_address  = di_start  + (di_index - 1)   # 例 DI12 → 10200 + 11 = 10211
```

默认值写在 [../wire-cabinet/slot-config/io-modules.template.yaml](../wire-cabinet/slot-config/io-modules.template.yaml) 的 `modbus.addressing`；若某块模块例外，可在该 `modules[]` 项覆盖 `do_start` / `di_start`。

**与旧草稿的区别**：此前文档写 `address = index - 1`（从 0 起算），**不适用本柜**；必须以 **100 / 10200** 为基址。

### 4.2 读写 API（实现选型）

- 推荐 NuGet：`NModbus` 或等价 Modbus TCP 客户端。
- 每 `module_key` 一个长连接客户端 + 互斥锁（同模块串行）。
- 周期健康检查：每 `health_check_interval_ms` 读 `ReadDiscreteInputs(di_start, 1)` 或读满 16 点探活。

### 4.3 批量读优化

每模块 DI 在 `[di_start .. di_start+15]` 连续，联锁轮询优先：

```text
ReadDiscreteInputs(di_start=10200, count=16)
```

再按 `slot-io-mapping` 的 `di_index` 取对应位。DO 批量读同理：`ReadCoils(do_start=100, count=16)`（维护界面用；开锁仍单点 `WriteCoil(coil_address, true)`）。

## 5. 锁反馈、DI 与联锁读数

> **术语**：锁状态反馈接 **DI**；**释锁后本柜门自动弹开**，无独立门磁，DI 释锁即视为该格门开。与 [概要设计 §2.1](格口硬件控制层-概要设计.md) 一致。

### 5.1 DI 原始电平与逻辑状态（现场已确认）

本柜锁状态反馈接入 IO 模块 DI，**Modbus 读回的离散量含义固定为**：

| DI 读数 | 锁机构含义 | `HardwareLockState` | 本柜门态（无门磁） |
|---------|------------|---------------------|-------------------|
| **1** | **锁闭合**（锁舌锁住） | `Locked` | 门已关且锁止（OP 手动关门后） |
| **0** | **锁释放**（开锁/未锁止） | `Unlocked` | 门自动弹开 |

配置项 `di_semantics.di_active_means_locked: true` 表示「**DI=1 → Locked**」；与上表一致，**0.1 不得改为 `false`**（除非换柜改线）。

实现伪代码：

```csharp
// raw: ReadDiscreteInputs 单点布尔，true 即 DI=1
var locked = di_active_means_locked ? raw : !raw;
return locked ? HardwareLockState.Locked : HardwareLockState.Unlocked;
```

| `di_active_means_locked` | DI=1 | DI=0 |
|--------------------------|------|------|
| `true`（**本柜**） | `Locked` | `Unlocked` |
| `false`（其他项目备用） | `Unlocked` | `Locked` |

### 5.2 ReadInterlockLockStatesAsync

```text
codes = app_slot 或配置中 is_enabled=1 且 io_wired=1 的 SlotCode 列表
for each code in codes:
  read DI → HardwareLockState
return Dictionary<SlotCode, HardwareLockState>
```

- 未启用或未接线的格口 **不读取、不参与** 联锁。
- 读失败记为 `ReadFailed`；上层聚合时按「未全关」处理并告警。

### 5.3 与 RCS 的关系

硬件层 **不** 构造 `DoorStateInput`。格口控制层读取本接口字典后聚合（并可合并 `app_slot.door_state`），再交给 `AgvOperationEvaluator`（见 [格口控制层-详细设计.md](格口控制层-详细设计.md) §4）。

> **遗留说明**：旧上位机用 `closeFlag` 位串；`AgvDispatch.Sdk` 仍提供 `DoorStateInput.FromCloseFlag` 供 Sample/单测。0.1 生产路径 **禁止** 依赖该字符串。

## 6. 开锁时序

### 6.1 hardware_pulse（0.1 默认，本柜 IO 模块）

现场 IO 模块各 DO 已配置为**硬件脉冲模式**。程序开锁时：

| 步骤 | 动作 |
|------|------|
| 1 | 若 `_unlockInProgress.Contains(slotCode)` → `ConcurrentUnlock` |
| 2 | 查映射：`wired`、`module.enabled` |
| 3 | 模块健康 `IsOnline` |
| 4 | **`WriteCoil(doAddress, true)` 一次** |
| 5 | **不** `WriteCoil(doAddress, false)`（模块自动输出脉冲并复位） |
| 6 | 循环读 DI 直至 `Unlocked` 或 `unlock_feedback_timeout_ms` |
| 7 | 成功 → `Success`；否则 `FeedbackTimeout` + 中文消息 |

脉冲宽度、边沿由 **模块本地配置** 决定；`io-modules.yaml` 中 `pulse_ms` **不参与** 本模式。验收前在模块侧确认脉冲参数与锁机构匹配。

### 6.2 software_pulse（可选，非本柜默认）

| 步骤 | 动作 |
|------|------|
| 4–6 | 写 true → `Delay(pulse_ms)` → 写 false，再由步骤 6 轮询 DI |

仅当 `unlock.output_mode: software_pulse` 时使用；**勿**与硬件脉冲模式混用同一 DO。

### 6.3 level（维护/调试）

持续电平输出，生产流程默认禁用。

## 7. 并发与线程

- 全局：同一 `slotCode` 不允许并发 `UnlockAsync`。
- 模块级：同一模块 IO 串行化（锁或 Channel）。
- `ReadInterlockLockStatesAsync` 可与开锁互斥排队，避免半读状态。

## 9. 启动校验

启动时执行（失败则禁止业务开锁）：

1. `slots` 与 `mappings` 条数一致，wired 映射 54 路。
2. 每个 `slot_code` 最多一条 `wired: true`。
3. 每个 wired 行的 `module_key` 在 `io-modules.yaml` 存在。
4. 可选：对每模块试连 Modbus（维护界面「格口硬件连接状态」）。

## 10. 中文错误码表

| Code | Message 模板 |
|------|----------------|
| ModuleOffline | IO 模块 {key} 离线，请检查网络与 IP |
| NotWired | 格口 {slotCode} 未接线，无法开锁 |
| SlotDisabled | 格口 {slotCode} 已禁用 |
| ConcurrentUnlock | 格口 {slotCode} 正在开锁，请稍后 |
| WriteFailed | 格口 {slotCode} 开锁指令下发失败 |
| FeedbackTimeout | 格口 {slotCode} 开锁超时，请检查门锁 |
| CommError | 与 IO 模块通信异常：{detail} |
| Success | 格口 {slotCode} 开锁成功 |

## 11. 类结构（建议）

```text
SlotHardwareService : ISlotHardwareService
  ├── SlotConfigStore          # 加载 yaml
  ├── ModbusModuleClientPool   # key → ModbusModuleClient
  └── UnlockCoordinator        # 并发、in-progress 集合

ModbusModuleClient
  ├── Connect / HealthCheck
  ├── WriteDoUnlock(doIndex, mode)  # coil = do_start + doIndex - 1；hardware_pulse 仅 true
  └── ReadDi(diIndex) → bool raw    # discrete = di_start + diIndex - 1
```

## 12. 示例：F-A01 映射

来自生成配置（节选）：

| slot_code | module | DO | DI | door_position |
|-----------|--------|----|----|---------------|
| F-A01 | C4 | DO12 | DI12 | front(1,1) |

开锁：连 `C4` → 写线圈 **111**（`100+12-1`）=true（一次）→ 模块硬件脉冲 → 读离散输入 **10211**（`10200+12-1`）→ 判定释放。

## 13. 测试要点（0.1 验收）

- B 级：≥2 个不同模块上的格口真开锁成功（见 [验收清单.md](../验收清单.md) §3）。
- 联锁：全部 enabled∧wired 格口 DI 为 `Locked` 时，`DoorStateInput.AllDoorsClosed == true`。
- 模块离线时 HMI 显示连接异常，且 `UnlockAsync` 返回 `ModuleOffline`。
