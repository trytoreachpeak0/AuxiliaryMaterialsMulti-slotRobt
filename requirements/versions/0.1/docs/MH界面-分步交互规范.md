# MH 存入可用焊丝界面 — 分步交互规范（0.1）

## 1. 布局参考

- 视觉与区块划分以 [`WireDispenser.Demo/Views/MhView.xaml`](../../../../WireDispenser.Demo/Views/MhView.xaml) 为准（左栏存料 + 右栏格口网格；1024×768 无滚动，见 [HMI界面约束](HMI界面约束.md)）。
- 业务顺序以流程 `material_handler_load_available_wire` 为准，与 flow-sql-map 段落见 §3。
- MH **格口维护**（单开/批量开）为独立流程，本规范仅覆盖 **存可用焊丝**；维护页可简化交互，但须遵守 [需求范围 §2.6](../需求范围.md) 会话互斥。

## 2. 核心规则（必须实现）

### 2.1 分步点亮

| 规则 | 说明 |
|------|------|
| 初始 | 仅**当前步骤**可交互；后续步骤置灰（建议 `Opacity≈0.45`）且 `IsEnabled=false`。 |
| 前进 | 当前步 **查询/开锁/确认** 成功后锁定该步，再点亮下一步。 |
| 锁定 | 已完成步的主输入与动作按钮不可再改；只读结果区（规格、分配格口）可保留。 |

### 2.2 级联清空

在可编辑步将**焊丝批号**清空时：

1. 清空该步及之后所有步的输入、查询结果、格口分配展示；
2. 流程回退到该步为当前可编辑步；
3. 已锁定更早步不变（存料链仅一步输入时通常无更早锁定项）。

须提供 **「清空」** 按钮（批号输入框右侧），一次性复位存料流程；等待关门期间禁用。

### 2.3 与到站门禁的关系

- **存可用焊丝**适用 [需求范围 §2.2](../需求范围.md)：须车在 **MH 作业站**（`allowed_roles` 含 MH）且顶栏为物料员；否则禁止开锁与写库。
- **MH 格口维护**（§3.3）**不要求到站**（与 OP/MH 存取区分）。

### 2.4 状态提示

当前步骤、校验失败、开锁结果走主窗口底部状态栏（或等价绑定），中文、可恢复。

### 2.5 未关格口恢复

程序异常退出或任一 MH 操作（**存料**、**格口批量控制**、**单格打开此格口**）执行后，若应用库/硬件仍显示有格口未关（`door_state='open'` 或锁 DI 释放）：

1. **禁止**一切新的 MH 格口相关操作，直至**全部**格口关闭；
2. 存料区：主按钮「检测有格口未关闭」（禁用）；批号输入与清空禁用；
3. 格口批量控制与「打开此格口」按钮禁用；若用户仍触发，提示先关格口；
4. 物料员关闭格口后，轮询与 `DoorStateReconciler` 回写库表，各区域自动恢复可交互。

存料流程等待关门（`WaitingClose`）期间，仅允许完成当前存料，不可并行开启其他格口或新存料。流程层与服务层二次校验，防止绕过 UI。

### 2.6 存料中断提醒

`openAvailableSlot` 成功后、写库前若程序异常退出，将格口与批号快照写入 `mh_interrupted_load`（不自动 `bind_wire`）。

重启 HMI 后：

1. 弹窗说明上次中断的格口、批号、规格；
2. **格口仍开**：提示取出焊丝（若已放入）、关好格口后重新扫码存料；用户确认后**保留**记录直至格口关好；
3. **格口已关**：提示先到该格口确认格内是否有焊丝，取出后回到物料间重新扫码存料；用户确认后**清除**记录；
4. 正常关门写库成功后自动清除记录。

存料仍须 AGV 在 MH 作业站；弹窗可在任意地点显示，重新存料须到站后执行。

## 3. 步骤与流程节点映射

| UI 步骤 | 界面区块 | 完成条件（通过后锁定） | flow-sql-map 段落 |
|---------|----------|------------------------|-------------------|
| ① | 焊丝批号输入 +「清空」+「输入焊丝」 | 一次提交：`checkAvailableSlot` → `queryWireSpecByLotNo` → `checkWireLotNoExists` → `checkWireSpecExists` → `queryAppWireLotNo` → `checkAppWireLotNoAlreadyExists` 均通过后**立即** `openAvailableSlot`；失败则提示错误且不开门 | `inputWireLotNo` + `openSlotLoadWire`（`openAvailableSlot`） |
| ② | 等待关门 + 自动写库 | 主按钮文案为「请将焊丝放入格口」；分配区显示完整格口（如「前柜 F-A03（空闲）」）；物料员放入焊丝并关门；系统检测门已关后自动 `closeAvailableSlotDoor` → `updateDB`（`app.slot.bind_wire`）；格口 `available_wire` | `openSlotLoadWire` / `updateDB` |

实现时步骤①在后台线程链式执行校验与开门，UI 不阻塞；批号校验通过后批号输入锁定，主按钮改为「请将焊丝放入格口」，无需再点「打开格口」按钮。写库完成或校验失败后，输入框与按钮恢复初始态，焦点回到批号输入框。

## 4. 实现建议

- 批号 `TextChanged`：等待关门期间不重置；其他状态下空白时复位存料 UI。
- 扫码枪输入末尾带回车：`WireLotBox` 监听 `KeyDown(Enter)`，在可提交时自动触发与「输入焊丝」相同的校验流程。
- 「清空」：Idle 态可点，调用 `ResetDepositUi()` 并提示重新输入；WaitingClose 态禁用。
- MES 查询、开门、写库在 `Task.Run` 后台执行，避免阻塞 WPF UI 线程。
- 处理期间主按钮显示「校验中…」并禁用（`_depositInProgress`），避免触屏连点。
- 校验通过进入等待关门后，主按钮显示「请将焊丝放入格口」（禁用）；分配区须含前/后柜与完整 `slot_no`。
- 批号不存在或已在柜内：错误区分别显示「焊丝批号不存在」「此批号已在柜内（前柜 F-xx）」；主按钮恢复「输入焊丝」，焦点回输入框并全选批号。
- 存料成功或失败后，焦点均回到批号输入框。

## 5. 验收要点

- [ ] 冷启动仅批号输入与「输入焊丝」可交互。
- [ ] 一次点击后：校验通过即自动开门，批号不可改，主按钮为「请将焊丝放入格口」，分配显示完整格口编号；校验失败提示错误且不开门，按钮恢复「输入焊丝」。
- [ ] 清空批号后存料状态复位（等待关门期间除外）；「清空」按钮行为符合 §2.2。
- [ ] 柜内已有相同批号时提示「此批号已在柜内（前柜 F-xx）」，不开门。
- [ ] 扫码枪扫入批号（末尾 Enter）自动触发校验，无需手点「输入焊丝」。
- [ ] 关门后自动写库并完成，界面回到初始态（输入清空、按钮「输入焊丝」、焦点在输入框）。
- [ ] 批号不存在/已在柜内时，焦点在输入框且批号全选。
- [ ] 未到站时不可开锁、不可完成写库。
- [ ] 操作过程中界面保持响应（不卡死）。
- [ ] 模拟开门后杀进程 → 重启：主按钮「检测有格口未关闭」且不可开第二格口；关格后恢复「输入焊丝」。
- [ ] 模拟开门后杀进程 → 重启：弹窗显示上次格口与批号；门仍开时确认后记录保留，门关后确认清除；正常写库后记录自动清除。
