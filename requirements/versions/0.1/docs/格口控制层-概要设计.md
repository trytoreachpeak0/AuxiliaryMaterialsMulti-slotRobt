## 2. 定位与职责

格口控制层对焊丝应用提供 **以 SlotCode 为中心** 的开锁、状态查询与 DB 同步；对下调用 [格口硬件控制层](格口硬件控制层-概要设计.md)。

```text
焊丝流程 / HMI（flow-sql-map、UI）
        ↕ ISlotControlService
格口控制层（门/锁状态、操作会话、联锁查询）
        ↕ ISlotHardwareService + 应用库 app_slot 表（SQL）
格口硬件控制层（Modbus）
```

**负责**：执行已授权的开锁、更新 **`app_slot` 门/锁列**、维护**唯一操作会话**（§2.2）、批量开锁编排、供 RCS 的门状态、联锁查询。格口**库存**（有无焊丝）由流程结束时的 SQL 写入，**开锁/关门过程不改 `biz_state`**。

**不负责**：OP 权限与 MES 校验（流程/应用层）；是否允许 MH/OP 界面操作（到站门禁在应用层）；焊丝批号/库存明细的 MES 写入（流程里其它 SQL，但格口上绑了哪盘丝会反映在 `app_slot` 部分字段）。

### 2.1 `app_slot` 是什么？

**`app_slot`** 是运行在触控屏本机（或业务服务器）上的 **应用数据库**（0.1 验证环境为 SQLite）里的 **格口表**：**一行 = 柜里一格**，记录用途、**库存**（`biz_state`）、**门/锁**（`door_state`/`lock_state`）及焊丝字段。

| 项 | 说明 |
|----|------|
| 与 MES 库 | **分开**。MES 查 OP、批号、机台等走 `mes.*` SQL；`app_slot` 只存**本柜**格口与柜内焊丝状态 |
| 与硬件配置 | **分开**。`wire-cabinet/slot-config/*.yaml` 管 Modbus；`app_slot` 管库存与门/锁。通过 `slot_no`（= SlotCode）与配置对齐 |
| 谁读写 | 焊丝 **flow-sql-map** 节点（`app.slot.get_status`、`app.slot.open`、`app.slot.update_state` 等）+ **格口控制层** 在开锁/关门后 UPDATE |
| 表结构 | 见 [wire-flow-lab app_slot.yaml](../../../validation/wire-flow-lab/data-access-sql/schema/tables/app_slot.yaml)；0.1 可增加 `is_enabled`、`door_position` 等列（见 [详细设计 §2](格口控制层-详细设计.md)） |

**格口控制层「更新 app_slot」** 典型包括：

- **开锁成功** → 只写 `door_state=open`、`lock_state=unlocked`（见 §2.1.1～2.1.2）；语义同 `app.slot.open`，**不写 `biz_state`**
- **关门** → `door_state=closed`、`lock_state=locked`（DI 已 Locked 或 OP 确认）
- **流程结束写库存** → 由 flow-sql-map 节点把 `biz_state` 改为 `idle` / `available_wire` / `returned_wire`（存完丝、取完丝之后）

#### 2.1.1 本柜机械特性（与状态字段）

| 物理行为 | 说明 |
|----------|------|
| 开锁（DO=1） | 锁释放后，**门自动弹开**，OP 不另用手拉门 |
| 无门磁 | 不单独读「门角度」；**DI=0（锁释放）** 即认为该格**门已开** |
| 关门 | **OP 手动把门关上**，锁舌合上后 **DI=1（锁闭合）**；软件再记 `door_state=closed` |

#### 2.1.2 开锁成功后写哪些列？

硬件 `UnlockAsync` 已成功（DO=1、DI 释锁、门自动弹开）后，**只更新门/锁两列**：

| 字段 | 写入值 | 含义 |
|------|--------|------|
| `door_state` | `open` | 该格门已开 |
| `lock_state` | `unlocked` | 锁已释放 |

**不改 `biz_state`**。`biz_state` 仍表示**柜内库存**（例如仍是 `idle` 直到存完丝才变 `available_wire`）。  
「这格正在用」靠 **§2.2 操作会话** + `door_state=open` / DI 判断，不靠 `processing`。

**关门**：OP 手动关门 → DI Locked → `door_state=closed`、`lock_state=locked`。  
**存/取完成**：流程节点再 UPDATE `biz_state` 与 `wire_*` 等。

联锁：任一格 DI 释锁或 `door_state=open` → 禁止 AGV 移动。  
找空格口：`biz_state=idle` **且** `door_state=closed`（见 `app.slot.find_available`）。

### 2.2 操作会话互斥（替代 `processing`）

0.1 规定：**触控屏同一时间只允许一个焊丝操作会话**（MH 存丝 / OP 存取 / MH 维护 三选一，不能叠两个流程界面）。

| 项 | 说明 |
|----|------|
| 接口 | `IWireOperationSession`：开始会话时 `TryBegin(flowId)`，结束或取消时 `End()` |
| 会话内 | 记录本流程已打开的 `slot_id` 列表（批量开多格也属同一会话） |
| 与 DB | 开锁只改门/锁；会话结束或取消时，若有门仍 `open` 应提示或强制关门 |
| 禁止 | 无会话时不得 `OpenSlotAsync`；有会话时禁止进入第二个 flow 界面 |

实现见 [格口控制层-详细设计 §3.3](格口控制层-详细设计.md)。
- 存取焊丝后 → 更新 `wire_lot_no`、`wire_spec` 等与该格绑定的字段

演示种子仅 8 格（wire-flow-lab）；验收前按 [slot-config](../wire-cabinet/slot-config/) 导入 **54 行** `app_slot`，每行 `slot_no` = 对应 SlotCode。

0.1 **无完整站点作业层**；「能不能开」由流程节点 + 到站/充电/会话状态在应用层组合判断。

## 3. 控制对象（0.1 子集）

### 3.1 格口 Slot

**标识分工**：库表主键 **`slot_id`**（自增）；**SlotCode**（如 `F-A01`）为唯一业务名，存 `slot_no`，用于界面、日志、硬件 `UnlockAsync`；流程节点可传 `slot_id` 或 `slot_no`。详见 [格口硬件控制层-概要设计 §3.2](格口硬件控制层-概要设计.md)。

| 属性 | 0.1 说明 |
|------|----------|
| `slot_id` | 表主键；库存、日志、流程 `selected_slot_id` |
| `slot_no` | **SlotCode**（唯一），与 [slot-config](../wire-cabinet/slot-config/) 的 `slot_code` 一致 |
| `door_position` | 可选落库，便于维护对照 |
| `is_enabled` | 未接线或维护中设为 false |
| 锁/门反馈 | 仅锁 DI；释锁=门自动开；无独立门磁 |
| 物体传感器 | **不接入** |

### 3.2 库存状态（`app_slot.biz_state`，仅表柜内有无料）

**0.1 不使用 `processing`**。`biz_state` **只表示焊丝库存**，开锁/关门过程中**不变**。

| 状态 | 含义 |
|------|------|
| `idle` | 格口空（无焊丝或未占用库存态） |
| `available_wire` | 柜内有可用焊丝 |
| `returned_wire` | 柜内有归还焊丝 |

进行中 → 看 `door_state`/`lock_state` + §2.2 会话，不看 `biz_state`。

> wire-flow-lab 枚举里仍有 `processing`，**0.1 实现与 SQL 不使用**；正式节点以本表三态为准。

### 3.2.1 MH 维护流程：无格内传感器 → 账面假定已清空

本柜 **无格内物体/焊丝检测传感器**，系统 **无法** 根据硬件判断 MH 是否真正把柜内焊丝取走。

因此 **物料员（MH）格口维护类流程**（`material_handler_open_single_slot`、`material_handler_open_all_*` 共 4 条；**不含** `material_handler_load_available_wire`）在流程中 **被打开过的每一格**，在 **关门确认且该流程正常结束** 时，库存按下列规则写库：

| 写库结果 | 说明 |
|----------|------|
| `biz_state = idle` | 账面视为 **空格口**（无可用/归还焊丝库存） |
| `wire_lot_no`、`wire_spec`、`wire_code` 等绑定字段 **清空** | 与「东西没了」一致，避免 OP 仍按旧批号匹配 |

**业务含义**：即使实物仍留在格内，**也以账面为准**（假定 MH 已处理完毕）；依赖 MH 操作规范与现场核对，必要时查操作日志。

**术语注意**：口语「变成可用/空了」对应枚举 **`idle`**（可再 `find_available` 存新料），**不是** `available_wire`（`available_wire` = 柜内 **仍有** 可用焊丝，仅用于 `load_available_wire` 存丝成功或 OP 领用后由流程显式写入）。

| 流程类型 | 关门后 `biz_state` |
|----------|-------------------|
| MH 维护（开格口取/整理，4 条） | `idle` + 清空焊丝字段 |
| MH 存入可用焊丝 `load_available_wire` | `available_wire` + `bind_wire`（有确认放入） |
| OP 存废取新 | 归还格 `returned_wire` / 领取后源格 `idle` 等（按 OP 节点 SQL，有 MES 与确认） |

实现：`updateSlot` / `updateCorrespondingSlots` 关门节点调用专用 SQL（建议 `app.slot.assume_empty`，见 [详细设计 §5.1](格口控制层-详细设计.md)）；当前 lab 的 `app.slot.update_state` 传空 `biz_state` **不会**改库存，**0.1 实现须补齐**。

### 3.3 门/锁状态（app_slot）

| 字段 | 值 |
|------|-----|
| `door_state` | `open` / `closed` |
| `lock_state` | `locked` / `unlocked` |

0.1：开锁成功即 `open`+`unlocked`（门自动开）；关门以 **DI 恢复 locked** 为主，OP 确认装/取完成为辅（见 §2.1.1）。

| 能力 | 0.1 |

## 5. 与焊丝流程（flow-sql-map）

| flow_id | 格口相关节点 | 控制层职责 |
|---------|--------------|------------|
| `material_handler_load_available_wire` | `openAvailableSlot` | 单开空格口 |
| `operator_return_wire_and_issue_available_wire` | 开回收 + 开新料 | 顺序双开 |
| `material_handler_open_single_slot` | `openSingleSlot` | 按选择单开 |
| `material_handler_open_all_*` | `openAll*` | 批量开 + 关门子图 |

节点 `access_type: slot_control` 由流程引擎调用 `ISlotControlService`，再执行 `app.slot.*` SQL（见详细设计映射表）。

## 6. 安全联锁（概要）

应用层组合以下条件（详见 [格口控制层-详细设计.md](格口控制层-详细设计.md) §联锁）：

- 任一格 **开锁中** → 禁止控车、禁止新开锁。
- **操作会话未结束**（§2.2）→ 同上。
- **门未全关**（DI + DB，见详细设计 §4）：
  - **出发前**：`!AllDoorsClosed` → 禁止下发移动单。
  - **移动中**：控车循环（如 `AgvControlLoop`）**每个 Tick 持续**调用 `GetDoorStateForAgvAsync()` 重读 DI/DB；任一格突开（锁损坏导致释锁、误触等）→ 立即 `PauseMovementAsync`；全关后 `ContinueMovementAsync`。
- **充电中** → **仅禁止焊丝开锁**；**不禁止控车**（可结束充电后离站、手动选站移动等，见 [需求范围.md](../需求范围.md) §7.2）。

格口控制层提供：`AreAllDoorsClosed()`、`HasUnlockInProgress()`、`GetDoorStateForAgvAsync()`（→ `DoorStateInput`）。

## 7. 与 RCS

- 实现 `IDoorStateProvider`（`CabinetDoorStateProvider`），内部调用 `ISlotControlService.GetDoorStateForAgvAsync()`。
- **不使用** 旧项目 `closeFlag` 位串；直接设置 `DoorStateInput.AllDoorsClosed` / `AnyDoorOpen`（见 [RCS协同层-0.1.md](RCS协同层-0.1.md)）。
- 门联锁与 **移动中持续监测** 在 RCS 轮询循环中消费上述门状态；与充电态解耦（充电不阻断控车循环）。
- 参与联锁的格口集合见 [slot-config/README.md](../wire-cabinet/slot-config/README.md)（enabled ∧ wired）。
