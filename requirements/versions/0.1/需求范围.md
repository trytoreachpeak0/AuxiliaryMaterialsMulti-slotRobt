# 0.1 版本需求范围

## 1. 版本定位

0.1 在短周期内交付 **焊丝柜 + MES + 真实格口 + 手动/自动控车** 的可演示系统。

### 1.1 主链路

```text
MH 存焊丝入柜 → 应用库记录库存与格口状态
    → OP 退旧焊丝、取同规格新焊丝（MES 校验与写库均真实联调）
    → MH 维护：单开 / 批量开格口
    → 手动将 AGV 移至作业站 → 到站后允许焊丝界面操作
    → 电量低 → 自动下充电单 → 充满后回 **充点前作业站**
```

### 1.2 设计原则

- 流程实现以 `requirements/flows/flow-sql-map/` 与 `diagrams/` 为准。
- **MES、RCS、已启用格口均真实联调**；不提供 Mock / 模拟接口模式。
- 不引入统一任务状态机；控车为 **手动移动会话** + **后台回充策略**，非任务池派单。

## 2. 角色与界面

| 角色 | 0.1 能力 |
|------|----------|
| **物料员 MH** | 存可用焊丝；开单个 / 所有可用 / 所有归还 / 所有格口 |
| **操作员 OP** | 存废取新（工号班组班次、机台、用量、退料、取新） |
| **维护/管理员** | 格口状态、操作日志、单格口试开锁、MES/RCS/格口连接状态查看 |

### 2.1 界面清单

- 顶栏 **操作员 OP / 物料员 MH** 角色切换（见 [HMI界面约束](docs/HMI界面约束.md)）
- MH 存焊丝（分步交互，见 [MH界面-分步交互规范](docs/MH界面-分步交互规范.md)）
- OP 存废取新（分步交互，见 [OP界面-分步交互规范](docs/OP界面-分步交互规范.md)）
- MH 格口维护（单开 + 三种批量开）
- **维护视图**：格口状态总览、单格口试开锁、MES/RCS/格口硬件连接状态（可与 MH 页或独立入口合并，须满足 §2 维护角色能力）
- 手动控车（选站、状态、当前站）
- 回充状态展示（电量、充电中、回驻点中）— 可与控车界面合并
- 操作日志查看或导出
- MES / RCS / 格口硬件连接状态提示（异常时可见，非 Mock 切换）

**UI 布局原型**：[`WireDispenser.Demo`](../../../WireDispenser.Demo/)（非 0.1 交付宿主，验收前确认正式工程路径，见 [开发待补齐 D8](docs/开发待补齐信息.md)）。

不要求：权限配置页、流程模板配置、MES 任务列表、监控大屏。

### 2.2 到站作业门禁

**含义**：未到焊丝柜 **作业站** 时，触控屏 **不允许** 做 MH/OP 存取焊丝（不开锁、不调 MES 写库）；不是 RCS 接口功能名，而是应用层统一判断。详见 [wire-cabinet/station-config/README.md](wire-cabinet/station-config/README.md) §2。

焊丝存取界面仅在同时满足时可用：

- 控车状态为 **已到站（Arrived）**；
- 当前 RCS `currentPosition` 与 **当前要用的作业站** 的 `rcs_destination` 一致；
- 触控屏顶栏角色（OP/MH）属于该站 `allowed_roles`，且打开的 flow 在该站 `allowed_wire_flows` 中（**MH 专用站** 仅 MH 存料，**OP 专用站** 仅 OP 存废取新，见 [wire-cabinet/wire-cabinet/station-config/](wire-cabinet/station-configREADME.md)）；
- 非 **充电中**、非 **移动中**（Sending/Moving）。

未到站或角色/站点不匹配：中文提示并禁止开锁与 MES 写库。MH 格口维护（§3.3）**不**适用本门禁。

### 2.3 OP 界面分步交互

OP 存废取新页须遵守 **分步点亮 → 通过后锁定 → 清空当前步则级联清空后续步**（详见 [OP界面-分步交互规范](docs/OP界面-分步交互规范.md)）。

### 2.4 HMI 一体机约束

分辨率、无滚动、触控尺寸、主题与角色壳见 [HMI界面约束](docs/HMI界面约束.md)。所有焊丝业务页须遵守。

### 2.5 MH 存料界面分步交互

MH 存入可用焊丝页须实现与 OP 同规则的分步交互（详见 [MH界面-分步交互规范](docs/MH界面-分步交互规范.md)）。MH 格口维护页不要求分步链，但须遵守 §2.6。

### 2.6 焊丝操作会话互斥

触控屏 **同一时间仅允许一个焊丝操作会话**（下列三选一，不可叠加）：

- MH 存入可用焊丝
- OP 存废取新
- MH 格口维护（单开或任一批量开流程）

有活跃会话时，禁止进入第二个 flow 界面；须中文提示「请先完成或退出当前操作」。与格口层 `IWireOperationSession` 一致（见 [格口控制层-概要设计](docs/格口控制层-概要设计.md)）。

## 3. 焊丝业务流程（6 条，均需实现）

流程定义见 `flow-sql-map/index.yaml`，图见 `flows/diagrams/`。

| flow_id | 名称 | 角色 | 0.1 要求 |
|---------|------|------|----------|
| `material_handler_load_available_wire` | 物料员存入可用焊丝 | MH | **必演示** |
| `operator_return_wire_and_issue_available_wire` | 操作员存废取新 | OP | **必演示** |
| `material_handler_open_single_slot` | 打开单个格口 | MH | 必实现，维护演示 |
| `material_handler_open_all_available_wire_slots` | 打开所有含可用焊丝格口 | MH | 必实现；批量开锁策略见 §7 |
| `material_handler_open_all_returned_wire_slots` | 打开所有含归还焊丝格口 | MH | 同上 |
| `material_handler_open_all_slots` | 打开所有格口 | MH | 同上 |

### 3.1 物料员存入可用焊丝

```text
输入/扫描批号 → 校验 → MES 查焊丝 → 规格存在性
→ 查可用空格口 → 开锁 → 确认放入 → 写应用库 → 格口「有新料」→ 日志
```

**异常（至少）**：批号空/格式错、MES 无批号、MES 异常、无空格口、开锁失败/超时、未确认放入。

### 3.2 操作员存废取新

与 `operator_return_wire_and_issue_available_wire`（flow-sql-map）一致，分 **归还** 与 **领用** 两段：

```text
【归还段】
输入 OP/班组/班次 → MES 校验 OP
→ 旧焊丝批号 → MES 规格 → 应用库匹配同规格新料 → 应用库归还重量
→ 机台号 → MES 机台 → 最近产品批（非 N/A）
→ 输入剩余芯片 → MES 用量核对（|差值|≤500；>500 提示后回环重输，见 showRemainingQtyWrongHint）
→ MES 退料提交（v_Task=归还）
→ findReturnSlot → 开归还格 → 提示放入 → 关门 → bind_returned_wire / 更新回收格口

【领用段】
→ MES 按产品批查产品信息（qty/step 有效）
→ MES 领用提交（同一 FUN_MAT_TRANS，v_Task=领用）
→ 开领用格（匹配可用焊丝格口）→ 提示取出 → 关门 → complete_issue_pickup → 日志
```

**异常（至少）**：OP 不存在；批号不存在；规格不存在；**归还重量不存在**；**无匹配可用焊丝**；机台不存在；产品批 N/A；用量失败（含 >500 须可重输）；退料失败；**无可用回收格口**；**产品信息不存在**；**领用提交失败**；任一格口开锁失败/超时。

### 3.3 物料员格口维护（4 条）

共性要求：

- 按流程图筛选目标格口（单个 / 有可用料 / 有归还料 / 全部）。
- **单开**：一次开一个格口，确认关门后更新状态。
- **批量开**：按序开锁；间隔 **300～500 ms**（默认 **400 ms**）；**任一格开锁失败立刻中止**整批（`StopOnFailure=true`）；关门阶段可逐个确认或批量确认（0.1 允许简化为一轮确认，但须在演示脚本中写明）。
- 维护流程 **不要求到站**（可在柜旁操作）；若业务要求仅到站后可维护，与 OP/MH 存取统一门禁。
- **无格内传感器**：本流程中 **被打开过的格口**，在关门且流程成功结束时，账面一律视为 **已清空** → `biz_state=idle`，并清空 `wire_*` 绑定字段；**即使实物未取走也按无料处理**（见 [格口控制层-概要设计 §3.2.1](docs/格口控制层-概要设计.md)）。**不含**「存入可用焊丝」流程（该流程存完后为 `available_wire`）。

## 4. 应用数据库

**0.1 运行时采用 SQLite**（文件库，见 [scripts/](scripts/) 建表/种子）；不以 SQL Server 作为柜端应用库。

以 `data-access-sql/schema` 为 MES 侧参考，0.1 应用库最小表：

### 4.1 格口

- 格口编号、显示名、启用、业务状态（空闲 / 有新料 / 回收占用 / 异常等）
- 与硬件 IO 映射关联（配置表或扩展字段）

### 4.2 柜内焊丝

- 批号、规格、物料编码、主批次、所在格口
- 状态：在柜待发、已取出、已回收等
- 入柜/出柜时间

### 4.3 操作日志

- 时间、操作人、类型、格口、批号、机台
- MES 结果、开锁结果、错误信息

### 4.4 控车日志（建议）

- 目标站、订单 id、移动状态、电量、是否回充、失败原因

不要求：完整配送任务表、任务明细、流程模板实例表。

## 5. 数据接口（MES + 应用库）

MES 优先使用 `data-access-sql/sql-catalog/items/`；应用库 SQL 以 lab 验证条目为准，逐步回写正式 catalog（见 [wire-flow-lab findings](../../validation/wire-flow-lab/findings.md) §四）。

### 5.1 MES 必须全部真实联调

| sql_id | 用途 |
|--------|------|
| `mes.operator.get_by_id` | OP 校验 |
| `mes.wire.get_by_lot_no` | 焊丝批号 / 规格 |
| `mes.eqp.get_by_wire_bonding_eqp_no` | 机台 |
| `mes.product.get_latest_product_lot_by_eqp` | 最近产品批 |
| `mes.wire_quota.check_quota` | 焊线用量核对 |
| `mes.product.query_product_by_lot_no` | 领用前产品 qty/step |
| `mes.mat_trans.submit_return` | **归还与领用共用** `FUN_MAT_TRANS_NEW`：`v_Task=归还`（退料）、`v_Task=领用`（领用），参数集见 catalog 说明 |

验收前须确认：测试库可用、写接口事务口径与现场一致；失败时按真实 MES 错误提示，不得本地伪造成功。

### 5.2 应用库必实现（0.1 运行时 SQLite）

## 6. 格口与硬件

**0.1 实现设计**（优先阅读）：

- [格口控制层-概要/详细设计](docs/格口控制层-概要设计.md)
- [格口硬件控制层-概要/详细设计](docs/格口硬件控制层-概要设计.md)
- [wire-cabinet/slot-config/](wire-cabinet/slot-config/)（由现场 xlsx 导出的 yaml）

母版：[格口控制层](../../baseline/格口控制层.md)、[格口硬件控制层](../../baseline/格口硬件控制层.md) 取 0.1 子集。  
现场源表：[仓位信息/](../../仓位信息/) 下 **仓位编号.xlsx**、**IO仓位对应表.xlsx**（见 [仓位信息/README.md](../../仓位信息/README.md)），不采用 `仓位数据结构.md` 草稿。

### 6.1 必须支持

- 按格口编号 **单开锁**；成功 / 失败 / 超时中文提示。
- 人工确认已放入 / 已取出；**关门**以 OP 手动关门且锁 DI 恢复 Locked 为依据（本柜释锁后门自动弹开，无门磁）。
- 锁状态 DI 必读：**DI=1 锁闭合、DI=0 锁释放**；释锁视为门开，供移动联锁（见 [格口硬件详细设计 §5.1](docs/格口硬件控制层-详细设计.md)）。
- **全柜格口可配置**（数量不写死，支持 **30 格及以上**）；未接线格口可禁用。
- 批量开格口（§3.3）在已启用格口上可执行。
- 格口占用与业务状态写入应用库。

### 6.2 移动 / 控车联锁

- **禁止下发移动单（出发前）**：任一格口正在开锁；OP/MH 存取会话未结束；门未全关（`IDoorStateProvider` → `AllDoorsClosed`，覆盖所有已启用且已接线格口，见 [格口控制层-详细设计.md](docs/格口控制层-详细设计.md) §4.3；**不用** 旧版 `closeFlag` 位串）。
- **移动中持续门监测**：控车循环每个 Tick 重读 DI+DB；任一格突开（含锁损坏导致释锁）→ `PauseMovementAsync`；全关后 `ContinueMovementAsync`（见 [agv-dispatch-sdk/docs/AGV调度场景与状态机.md](wire-cabinet/agv-dispatch-sdk/docs/AGV调度场景与状态机.md) 场景 C、[格口控制层-概要设计.md](docs/格口控制层-概要设计.md) §6）。

### 6.3 0.1 不要求

- 物体检测强制校验。
- 全柜逐格出厂验收报告（见验收清单分级）。
- 完整异常锁定 / 格口长期禁用策略（仅基本提示即可）。

## 7. RCS 协同层（控车与回充）

0.1 范围裁剪见 [RCS协同层-0.1.md](docs/RCS协同层-0.1.md)。  
API、场景、配置、示例代码见 [wire-cabinet/agv-dispatch-sdk/](wire-cabinet/agv-dispatch-sdk/)（不在此重复）。

### 7.1 手动控车

- 界面选择 **作业站**（来自站点配置表，含 RCS 整型 `destination`）。
- 移动前检查（§6.2 + SDK `AgvOperationEvaluator`）。
- `CreateMoveOrderAsync` 下单；HTTP 轮询（无推送）。
- UI 状态机：`Idle` → `Sending` → `Moving` → `Arrived` / `Failed` / `Timeout`。
- **到站判定**：`currentPosition ==` 下单目标站（见 SDK 场景 D）。
- 到站后放开 §2.2 焊丝作业门禁。
- 移动过程写入控车日志。
- **必须连接真实 RCS**；不提供本地模拟到站或假下单。

### 7.2 低电量自动回充

- 轮询 `battery`（及可选 `sys_state == CHARGING`）。
- 低于 **低电量阈值**（可配置，验收前冻结）：自动 `CreateChargeOrderAsync`；充电桩占用时 `IsChargeStationOccupied` 为 true 则等待。
- **充电中**：**禁止焊丝开锁**；**允许控车**（手动/自动 `CreateMoveOrderAsync`，如结束充电后离站、回作业站）；与格口联锁解耦。
- > 集成注意：[AgvOperationEvaluator](wire-cabinet/agv-dispatch-sdk/AgvDispatch.Sdk/Operations/AgvOperationEvaluator.cs) Sample 对 `CHARGING` 仍返回「不可下单」；0.1 业务实现须按本条放宽（移除该早退或应用层单独下发）。
- 达到 **充电完成阈值** 或离开充电态：自动 `CreateMoveOrderAsync` 回到 **去充电前记录的作业站**（`return_to_last_work_station`，见 [wire-cabinet/wire-cabinet/station-config/](wire-cabinet/station-configREADME.md)）；**不设单独驻点**。
- 回充、返航过程可见状态与日志。

### 7.3 站点配置（业务维护，非 SDK 内置）

仅两类站点（YAML 见 [wire-cabinet/station-config/stations.template.yaml](wire-cabinet/station-config/stations.template.yaml)）：

| 类型 | 用途 |
|------|------|
| **作业站** `work` | 可多个；每站 `allowed_roles`（`OP` / `MH`）+ `allowed_wire_flows`；到站且角色匹配后才可存取 |
| **充电点** `charge` | **0.1 仅 1 个**；低电量充电；充完返回上一作业站 |

典型划分：**MH 作业站** 仅 `material_handler_load_available_wire`；**OP 作业站** 仅 `operator_return_wire_and_issue_available_wire`。详见 [wire-cabinet/station-config/README.md](wire-cabinet/station-config/README.md)。

### 7.4 0.1 控车不要求

- 多车选择、任务优先级、订单改派。
- 与 MES 任务绑定的自动派车。
- 完整机器人任务层状态机（后续版本）。

## 8. 0.1 明确不做

- MES 自动获取 / 推送任务
- 任务池、排队、优先级、人工创建配送任务
- 内部统一业务任务状态机（除控车会话与回充状态外）
- 流程模板引擎、完整站点作业层
- 多点配送、多点收料
- 多车、多柜、RCS 路径与调度策略
- 全角色权限矩阵、全量 MES 异常回传、完整审计报表
- 接口 Mock、模拟 MES/RCS/格口、模拟到站
