# WireFlowLab 焊丝发放流程验证工具 — 使用文档

本工具用于验证焊丝发放的 6 个流程是否能跑通、流程图与 `data-access-sql`（`flow-sql-map` / `sql-catalog`）是否正确、SQL 的入参/结果/分支是否对得上。

- 应用数据库：真实 SQLite 执行。
- MES：默认 SQLite mock（可切换真实 Oracle）。
- 格口仓门：mock 模拟，带可视化面板。

---

## 1. 环境与启动

前置：Windows + 已安装 .NET 8 SDK（WPF 需要桌面环境运行）。

```powershell
cd requirements/validation/wire-flow-lab/src
dotnet restore
dotnet build WireFlowLab.sln

# 启动图形界面
dotnet run --project WireFlowLab/WireFlowLab.csproj

# 或：无界面自测（自动跑完 6 个流程，结果写到 db/selftest-output.txt）
dotnet run --project WireFlowLab/WireFlowLab.csproj -- selftest
```

**首次启动自动建库**：工具会在 `db/app.db` 执行 `db/schema.sqlite.sql` + `db/seed.sqlite.sql`，把应用库表和 MES mock 表灌入种子数据（应用库与 MES mock 共用同一个 SQLite 文件）。

## 2. 界面总览

界面分四块区域：

```
┌─────────────────────────────────────────────────────────────────┐
│ 顶部工具栏：流程选择 + 开始/单步/连续 + 重置/校验/自测/导出           │
├──────────────────┬──────────────────┬───────────────────────────┤
│ 左：执行轨迹      │ 中：当前节点/输入 │ 右上：MES 设置             │

├──────────────────┴──────────────────┴───────────────────────────┤
│ 底部：验证结论 Findings 表                                          │
├───────────────────────────────────────────────────────────────────┤
│ 状态栏（最下方深色条，显示当前操作提示）                              │
└───────────────────────────────────────────────────────────────────┘
```

## 3. 顶部工具栏

| 控件 | 作用 |
|---|---|
| **流程下拉框** | 选择要验证的流程（6 选 1）。 |
| **开始** | 在干净数据库上开始所选流程：重置数据库 → 清空 trace/findings → 先跑一次该流程的静态校验 → 定位到起始节点等待执行。 |
| **单步 ▶** | 执行当前一个节点，前进一步。若当前是输入节点，会先读取「中栏」里你填的输入值。 |
| **连续执行 ⏩** | 从当前节点一直自动跑到流程结束（输入节点用当前/默认值），最多 300 步防死循环。 |
| **重置数据库** | 删除并重建 `app.db`，重新灌种子，格口/库存/MES mock 数据回到初始状态，并清空 trace。数据被改乱后用它复位。 |
| **校验全部流程** | 对 6 个流程做**静态校验**（不执行），把发现的问题填到底部 findings 表。 |
| **无界面自测** | 后台自动跑完全部 6 个流程主路径（静态校验 + 真实执行），把完整 trace 写到 `db/selftest-output.txt`。 |
| **导出 findings** | 把底部 findings 表当前内容按级别分组导出为 `db/findings-export.md`。 |

> 区别提示：**单步/连续执行**是「真的跑流程、跑 SQL」；**校验全部流程**是「只看 YAML 结构、不跑」；**无界面自测**是「一键自动跑完 6 个流程并存文件」。

## 4. 左栏：执行轨迹 Trace

每执行一个节点新增一行，列含义：

| 列 | 含义 |
|---|---|
| # | 步序号 |
| 节点 | 节点 id |
| 类型 | user_input / query / decision / write / slot_open / slot_open_batch / slot_close / terminal |
| 结果key | 该步的结果分支键（single/empty/multiple/error、yes/no、success 等） |
| 下一步 | 根据 `outcome_routing` 跳转到的下一个节点（END 表示结束） |
| SQL | 实际渲染（已代入参数）的 SQL；mock 函数显示 `[mock] ...` |
| 结果 | 查询行数/字段值、写入影响行数、判定明细等 |

行底色：**红=该步有 Error**，**黄=有 Warning**，白=正常。

---

## 5. 中栏：当前节点 / 输入

- 上方卡片显示**当前节点**的 id、说明文字、类型。
- 当当前节点是**输入节点**（user_input）时，下面出现输入框（如工号、批号、机台号、数量等），已带默认值；改完后点顶部「单步 ▶」推进。
- 非输入节点时这里只展示节点信息，直接点「单步/连续执行」即可。

各流程默认输入值（种子数据）：操作员 `1001`(张三)、归还批号 `14Z1888-0160`、可用批号 `14Z1888-0888`、机台 `1QH029`、规格 `φ42(MAXSOFT)`。

---

## 6. 右上：MES 设置

控制 MES 这一侧用 mock 还是真库，改完务必点 **「应用 MES 设置」** 才生效。

| 控件 | 作用 |
|---|---|
| **使用真实 Oracle MES**（勾选框） | 勾选=连真实 Oracle，用 `mes_mock.*` 里保留的原生 Oracle SQL/存储函数；取消=SQLite mock。 |
| **Oracle 连接串** | 勾选 Oracle 时填，如 `User Id=mes;Password=***;Data Source=host:1521/ORCLPDB`。 |
| **配额差值** | SQLite mock 下 `Get_Mat_QuotaCheck` 的返回值。`≤500` 允许归还，`>500` 触发「数量有误」分支。 |
| **提交结果** | SQLite mock 下 `FUN_MAT_TRANS_NEW` 的返回值。`SUCCESS`/空/含 `ORA-01403` 视为成功，其余（如 `ERROR: xxx`）视为失败。 |
| **系统 AGV 编号** | 提交事务时作为 `v_Writer` 系统参数传入。 |

> 用途举例：把「配额差值」改成 `600` 再跑操作员流程，就能验证配额超限分支；把「提交结果」改成 `ERROR: quota` 就能验证归还/领用提交失败分支。

---

## 7. 右下：格口仓库（mock 仓门）

每个格口一个卡片，显示：格口号、业务状态（颜色块）、门开/关、锁状态、绑定的焊丝批号与规格。

- 卡片**底色**：浅红=门开，浅绿=门关。
- 业务状态色块：蓝=含可用焊丝、黄=含归还焊丝、紫=处理中、灰=空闲。
- **开门 / 关门** 按钮：手动控制该格口的门。门状态会真实写回 `app_slot.door_state`，所以「所有门是否关闭」的判定读到的是真实状态。

> 在「打开格口」类流程中，循环到「等待门关闭」时，可在面板手动点「关门」驱动流程继续；也可以直接「单步/连续执行」让引擎自动逐个关门。

## 8. 底部：验证结论 Findings 表

汇总静态校验 + 运行时发现的问题，五列：

| 列 | 含义 |
|---|---|
| 级别 | Error / Warning / Info |
| 流程 | 所属流程 id |
| 节点 | 出问题的节点 id |
| 类别 | 断链 / 缺少SQL / 入参来源 / 入参顺序 / 不可达 / 分支不全 / 死路 / 未路由 / 判定缺失 / 空集合 等 |
| 说明 | 具体描述 |

来源：
1. 点「开始」某流程或「校验全部流程」时的**静态校验**。
2. 「单步/连续执行」时每步产生的**运行时**发现（如 SQL 报错、结果基数无对应分支等）。

点「导出 findings」可把当前表内容存成 `db/findings-export.md`。

> 注意：这是工具运行期自动生成的 findings；另有一份我手工整理的结论文档 `wire-flow-lab/findings.md`（含流程图 vs map 差异、SQL/schema 一致性问题等），两者是不同文件。

## 9. 典型操作流程

### A. 跑通一个流程的主路径
1. 顶部选流程（如「操作员存入归还焊丝并取出可用焊丝」）。
2. 点「开始」。
3. 中栏出现输入框时填好（或用默认），点「单步 ▶」逐步推进；想一口气跑完点「连续执行 ⏩」。
4. 看左栏 trace 每步的 SQL/结果/分支，看右下格口面板变化，看底部有无 findings。

### B. 验证某个异常分支
1. 点「开始」。
2. 按 `scenarios/` 里的说明改输入或 MES 设置（如配额差值 600、提交结果 ERROR:xxx、批号填不存在的值）。
3. 执行，确认是否走到预期的失败/提示终止节点。

### C. 一键回归 6 个流程
- 直接点「无界面自测」，然后打开 `db/selftest-output.txt` 看完整 trace 和 findings 汇总。
- 或命令行 `dotnet run ... -- selftest`。

### D. 只检查 YAML 结构是否有错
- 点「校验全部流程」，看底部表里是否有 Error（断链、缺 SQL、入参来源缺失等）。

## 10. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 跑了几次后格口/数据不对 | 点「重置数据库」复位到种子状态。 |
| 切了 Oracle 但连不上 | trace 里该 MES 步会显示连接错误；没真库就取消勾选回到 SQLite mock 并「应用 MES 设置」。 |
| 「连续执行」停在「达到步数上限」 | 流程可能存在回环/死循环，检查对应流程的 `outcome_routing`。 |
| 想换默认输入值 | 在中栏输入框直接改，或改 `flow.yaml` 里节点 `outputs` 的 `default`。 |
| 找不到 db/data-access-sql | 工具从运行目录向上查找 `wire-flow-lab`（含 `data-access-sql` 与 `db`）；请在仓库内运行。 |

## 11. 关联资料

- 流程编排（含补齐的 SQL 映射）：`data-access-sql/flow-sql-map/flows/<flow_id>/flow.yaml`
- SQL 清单：`data-access-sql/sql-catalog/items/`（`app.*` 应用库、`mes_mock.*` MES）
- 表结构：`data-access-sql/schema/`
- 建库/种子脚本：`db/schema.sqlite.sql`、`db/seed.sqlite.sql`
- 验证场景：`scenarios/`
- 结论文档：`findings.md`
- 自测输出：`db/selftest-output.txt`
