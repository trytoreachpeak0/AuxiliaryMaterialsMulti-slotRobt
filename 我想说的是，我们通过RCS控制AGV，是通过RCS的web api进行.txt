我想说的是，我们通过RCS控制AGV，是通过RCS的web api进行控制的，走的是http协议。然后是靠主动轮询，没有回调和推送机制
这个RCS提供这些功能（有其他功能但是用不上）
1. 登录管理
需要通过访问特定api进行登录，登陆后会给bearer的验证方式，然后之后都需要用这个bearer访问其他的web api

2.订单管理和任务状态
AGV移动靠给指定AGV下订单，新建订单，然后订单的任务选移动，输入订单名称，优先级，并指定机器人，就可以下达AGV的移动订单

然后这个任务会分为几种状态：
 队列中：刚下订单，订单在队列中，如果满足运行条件（AGV空闲+AGV启用+AGV没有其他订单），转入执行中，也可以已取消，还可以让这个队列优先执行（比如有多个订单可以）
执行中：AGV执行订单，可转入已取消，也可以暂停（转入已暂停）
已挂起：可从执行中转过来，说明AGV发生异常无法执行订单里的某个动作，可继续订单或者取消订单
已完成：已经完成的订单
已暂停：被暂停的订单，可以恢复到执行中
已取消：被取消的订单

3. 充电
RCS有内置的充电机制，但是因为控制逻辑锁死在RCS的程序里面了无法控制，所以只能靠下订单充电，订单任务选移动+充电动作，移动的目的地应该是应该充电桩，然后这个充电的话，我觉得应该在自己的系统里定义充电桩，充电桩规则和逻辑。（哪些车可以去某个充电桩，什么时候逻辑符合了就去冲）

4. AGV状态和信息
1) devicekey: agv在系统里有一个唯一的devicekey，然后很多api都会用这个devicekey作为参数
2) deviceName 设备名
3) sysState 设备状态
4) locationState 定位状态
5) orderTaskId 当前指定订单id
6) battery 点亮
7) enable 启用状态（可调度，可执行任务）
8) currentPosition 当前站点，可辅助判断车子是否到站
9) procState 当前任务/流程/工艺的执行状态
5) breakSwState 解抱闸状态
